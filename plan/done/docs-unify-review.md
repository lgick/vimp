## Этап 3. Автотест документации (защита от регресса) ✅ выполнен

**Проблема.** Этап 5 прошёл «0 битых ссылок» по разовому скрипту, который проверял только
существование файлов, не якоря. Паритет EN/RU, константы и версии крейта проверялись вручную.
Правило репозитория: функциональный/регрессионный контроль — в `tests/`.

**Решение.** Новый файл `tests/scripts/docs.test.js` (проект `engine-node` уже включает
`tests/scripts/**`; менять `vitest.config.js` не нужно). Чистый Node, без новых зависимостей
(`node:fs`, `node:path`). Тесты:

- 3.1 **Ссылки.** Для каждого `docs/{en,ru,ai}/*.md` (код-блоки `` вырезать регуляркой
`/``[\s\S]*?```/g`, inline-код с `[...]`не парсить) собрать`](target)`; пропускать
`http(s):`, `mailto:`. Файл должен существовать; если есть `#якорь`и цель`.md`— якорь
должен быть в наборе якорей цели. Якорь заголовка:`trim → toLowerCase → убрать ` →
удалить всё кроме букв/цифр/пробелов/`_`/`-`(флаг`u`, `\p{L}\p{N}`) → пробелы в `-`.
Дубликаты заголовков получают суффикс `-1`, `-2`— учесть. Допустимый список исключений —
явный массив в тесте с комментарием «почему» (самоссылки client.md с точками/слэшами в
заголовке, если окажутся ложными; шаблон-регулярка`[\w\s#]{0,13}`внутри plugin-api.md —
это не ссылка, а код: его исключать тем, что цель содержит`\` или `{`).
- 3.2 **Паритет EN/RU.** Совпадают наборы имён файлов `docs/en` и `docs/ru`; для каждой пары
  совпадают число заголовков, число таблиц-строк (`^\|`), число код-блоков, число `- [ ]`
  (вне код-блоков).
- 3.3 **Константы.** Прочитать значения из кода регулярками: `ENGINE_API_VERSION`,
  `SNAPSHOT_FORMAT_VERSION` (`packages/engine/src/config/opcodes.js`), `HANDOFF_VERSION`
  (`packages/engine/src/host/HostGame.js`), `PLAYER_STATE_LEN`, `WORLD_VOICE_LIMIT`
  (найти `git grep -n "PLAYER_STATE_LEN\|WORLD_VOICE_LIMIT" packages/engine`). Проверить, что в
  `docs/{en,ru,ai}` не встречается их «чужое» значение в характерных формах:
  `` `ENGINE_API_VERSION = N` ``, `"engineApi": N`, `SNAPSHOT_FORMAT_VERSION = N`,
  `(v N)` рядом со «snapshot»/«кадр», `PLAYER_STATE_LEN = N`.
- 3.4 **Версия крейта.** `vimp-engine-core = "X.Y"` в `docs/{en,ru}/core.md` совпадает с
  `major.minor` из `packages/engine/core/Cargo.toml` — иначе тест падает при релизе (это и
  есть сигнал обновить доку). Альтернатива без хрупкости — в `core.md` писать `"X.Y"`
  с пояснением «минорная версия крейта из `core/Cargo.toml`»; **выбрать вариант вместе с
  разработчиком до кода** (наблюдаемого эффекта на код нет, но это политика поддержки доков).
- 3.5 **Правила контракта.** Множество `Axx…E7` в таблице `docs/en/pitfalls.md` ("Contract
  rules at a glance") совпадает с `id:` в `packages/engine/src/devtools/contract/rules/*.js`
  (кроме `index.js`), а колонка Level — с `level: ERROR|WARN` правила.

Сначала запустить тест на текущем дереве: он ДОЛЖЕН упасть на п.1 (до этапа 1) — это
подтверждает, что тест ловит дефект; затем довести этапы 1, 5 до зелёного.

**Критерий.** `npx vitest run tests/scripts/docs.test.js --reporter=dot` зелёный; в `docs/`
специально испорченный якорь/константа его валит (проверить руками и откатить).
