# Реестр игр и dedicated-сервер: исправления по итогам тестирования

dedicated-сервера, плюс восьмая правка (этап 7), выделенная по ходу разбора
замечания № 2. Все семь замечаний проверены по коду и подтвердились; у двух
(№ 2 и № 7) настоящая причина отличается от описанной в замечании — см.
соответствующие этапы.

Этапы пронумерованы **в порядке исполнения**, а не в порядке исходного
списка замечаний.

Два уточнения:

- **№ 7.** Резолвинг `node_modules` вверх по дереву описан в замечании
  верно, но это следствие. Причина: `loadGamePackage` безусловно импортирует
  **обе** половины плагина, а dedicated-серверу клиентская не нужна ни разу.
  Вбандлить `pixi.js` в игру нельзя — это прямой запрет контракта
  (`devtools/contract/rules/a1-package-fields.js`): вторая копия PixiJS даёт
  второй реестр расширений и сломанный рендер.
- **№ 2.** Вёрстка исправна: `view/Games.js:234` уже печатает `Author:` с
  запасным прочерком. Автора нет **в данных**: миграция `009_games.sql:33`
  засеяла `tanks`/`snakes` с `author_user_id = NULL`.

## Решения заказчика

1. `Game id`, `Title`, `Repository URL` из формы убрать — показывать в
   предпросмотре; вводятся только `npm package` и `Version`.
2. Кнопка «My games» видна **всем**; заявку может подать любой
   авторизованный; заявитель автоматически становится автором; авторство
   меняет админ. Роль `developer` не заводится, привязка к GitHub не
   делается (вход скоро будет и через google/apple).
7. Ленивая загрузка client-половины. Симлинк `node_modules` в томе и
   бандлинг pixi в игру — отвергнуты.
Дополнительно: роль `superadmin` убирается, остаются `user` | `admin`,
единственный источник админских прав — `VIMP_ADMIN_NICKS` (этап 7).

## Release impact (по `CLAUDE.md`)

- Затрагивается npm-пакет `vimp-engine` (этапы 1, 2, 3, 6, 7) — суммарный
  уровень **minor** (задают `### Added` этапов 2 и 6).
- Крейт `vimp-engine-core` не затрагивается — репозиторию игры следовать не
  за чем.
- `packages/engine/contract/surface.json` не трогается: ни одна строка не
  удаляется, `ENGINE_API_VERSION` остаётся 4. Правило A1 (`pixi.js`
  external) сохраняется в силе.
- Auth-сервис (этапы 6, 7) — отдельный деплой-артефакт. Этапу 6 миграции не
  нужны; этап 7 добавляет `011_drop_superadmin.sql`, её нужно прогнать на
  проде (`npm run auth:db:migrate`). Порядок выката этапа 7: сначала
  auth-сервис с миграцией, затем мастера.
- Скрипты `.github/deployment/` и `deploy.yml` (этапы 4, 5) ни в один
  публикуемый артефакт не входят — записей в changelog не требуют.
- Версии в `package.json` не править, `npm run release` не запускать — это
  делает разработчик.

## Проверка

После **каждого** этапа:

```bash
npx eslint . && npm test -- --silent
```

Дополнительно:

- этапы 1 и 3: `npm run sim:check`;
- этап 1: `node packages/engine/bin/vimp-contract.js --game <dir>` на
  локальной игре — вердикт не меняется;
- этап 2, вручную: `npm run dev`, войти в лобби, «My games» → ввести
  `@vimp-games/tanks` → «Load» → в предпросмотре появляются id, title,
  репозиторий и список версий → «Submit for review» заводит заявку;
- этап 6, вручную: в «Moderation» назначить себя автором `tanks` → игра
  появляется в «My games», доступен запрос новой версии;
- этап 7, вручную: после миграции войти ником из `VIMP_ADMIN_NICKS` — панель
  «Moderation» видна; убрать ник из списка, перевойти — панель исчезает, а
  `/admin/games` отвечает 403;
- этапы 3–5, на тестовом VPS: `add-dedicated.sh` с пустым auth-URL, игра
  названа `@vimp-games/tanks` → сервер поднимается, пакет приезжает в
  `/var/vimp/games/tanks/<version>/`, ошибки `pixi.js` нет; затем добавить
  `settings` в `SERVERS_MATRIX`, прогнать деплой и убедиться, что
  `VIMP_DEDICATED_ROOM` в `.env.prod` пережил перегенерацию, а на
  лобби-мастерах (без `dedicatedGame`) этой переменной нет.
