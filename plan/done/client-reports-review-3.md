## Этап 2. Проверка «без стека в журнале» в тестах маршрута пустая (№2) ✅ выполнен

**Файл:** `tests/master/clientReportRoute.test.js`.

**Причина.** Express печатает стек в обработчике по умолчанию, только когда
`app.get('env') !== 'test'`. Под Vitest `NODE_ENV=test`, поэтому
`expect(consoleError).not.toHaveBeenCalled()` проходит и без исправления
`bodyError`.

**Решение.**

1. Хелпер `start()`: добавить параметр `env` и задавать его приложению.

   ```js
   async function start({ limit = 100, trustProxy = false, buffer, symbolicate = null, env } = {}) {
     const log = { warn: vi.fn(), error: vi.fn(), info: vi.fn() };
     const buf = buffer ?? new ClientReportBuffer();
     const app = express();

     // обработчик ошибок Express по умолчанию печатает стек только вне
     // `test` — а Vitest ставит NODE_ENV=test; тестам «без стека в журнале»
     // нужен боевой режим, иначе их проверка пустая
     if (env) {
       app.set('env', env);
     }
     …
   ```

2. В двух тестах «битый JSON: короткий JSON 400, без стека в журнале
   процесса» и «тело больше лимита: короткий JSON 413, без стека в журнале
   процесса» вызвать `start({ env: 'production' })` вместо `start()`.

**Проверка, что тест теперь настоящий** (временно, без коммита и без
сохранения правки):

1. В `packages/engine/src/master/clientReports/createClientReportRoute.js`
   убрать `bodyError` из возвращаемого массива.
2. Запустить `npx vitest run tests/master/clientReportRoute.test.js
   --reporter=dot` — оба теста падают, в том числе на `consoleError`.
3. Вернуть файл: `git checkout -- packages/engine/src/master/clientReports/createClientReportRoute.js`.

Затем — `npx eslint .` и `npx vitest run --reporter=dot` зелёные.

Журнала нет (тесты — не запись), документации нет.

**Дополнение при исполнении (согласовано).** Одного `env: 'production'`
мало: `finalhandler` пишет стек через `setImmediate` уже после ответа, и в
тесте с битым JSON `expect(consoleError)` успевал выполниться раньше. Перед
этой проверкой в обоих тестах добавлено `await new Promise(resolve =>
setImmediate(resolve))`. После этого удаление `bodyError` роняет обе проверки
`consoleError`.
