# Этап 1. Эталон Rapier и причина B (`obb_manifold`) ✅ выполнен

Индекс и общий контекст — `plan/README.md`. Правила и запреты оттуда действуют здесь.

## Причина

### Причина B: `collision::obb_manifold` — ложный контакт у разведённой пары «угол к углу»

- При пустом отсечении граней (`clip_segment` → `None`) и при отсеве всех точек (`len == 0`) функция откатывается к
  «смешанной» точке `obb_vs_obb_within`. Так сделано намеренно, см. doc-комментарий: «манифольда там нет, а контакт
  есть».
- Для РАЗВЕДЁННОЙ пары (`axis.depth < 0`), грани которой не перекрываются по касательной, у хоста контакта нет.
  Parry отсекает опорные грани, и при пустом пересечении точек нет. Реплика же получает контакт с нормалью по оси
  SAT и точкой в середине грани.
- Замер: `vimp-tanks`, карта `terraces`, танк 12×9 на скорости ≈260 проезжает проём шириной 12.8 в западной стене
  террасы (x ≈ 192, блоки `(185.6, 217.6)` и `(185.6, 339.2)`, полуразмеры по 6.4 по x).
  - На позе начала шага зазор по x = 2.165, по y = 1.9. SAT выбирает ось x, откат даёт точку
    `(194.16, 275.2)` — середину лба.
  - Скорость −265 закрывает «зазор» 2.165 быстрее шага: реплика режет скорость до −259.5, хост едет дальше
    (−258.6 после демпфирования).
- Сейчас это расхождение ≈1 ед/с за один шаг, оно безвредно. Но после исправления причины A такой контакт даёт
  полный отскок: реплика встаёт посреди проёма. Прототип это подтвердил: сломались сценарии `jump.json` и
  `downtown_bridge.json` игры (Δ ≈ 260 по скорости). **Поэтому причину B исправлять обязательно и ДО причины A.**

## Решение

### Правка `obb_manifold` (поведение, `### Fixed`)

В `packages/engine/core/src/client/collision.rs`, `obb_manifold`:
- обе ветки отката (`let Some(clipped) = clipped else { … }` и `if len == 0 { … }`) для разведённой пары
  (`axis.depth < 0.0`) возвращают `None`;
- при проникновении (`axis.depth >= 0.0`) откат остаётся прежним, бит в бит;
- `obb_vs_obb_within` и `obb_vs_obb` не меняются;
- поправить doc-комментарий функции: откат только при проникновении, а разведённая пара без перекрытия граней
  контакта не даёт, как у parry.

### Шаг 0. Эталон Rapier (тесты-свидетели, без правки кода) ✅ выполнен

Эталон в дереве: `rigid_body.rs`, помощник `rapier_head_on` и свидетель `rapier_head_on_regimes` (с ним этап 2,
шаг 1, сравнивает реплику); `collision.rs`, свидетель `rapier_has_no_contact_for_a_separated_corner_to_corner_pair`.
Проникновение на шаге удара у Rapier доходит до 0.041 (режим 0.77), не 0.03.

1. **Лобовой удар по режимам зазора.** Помощник `rapier_head_on(speed, wall_face, steps)`: мир как у хоста
   (`game.rs`: без гравитации, `dt` 1/120, остальное по умолчанию), танк 8×6, плотность 200, трение 0.5, упругость
   0.1, демпфирование 3/100, `soft_ccd_prediction` 6; стена — фиксированный кубоид с `DEFAULT_FRICTION` /
   `DEFAULT_RESTITUTION`. Тест-свидетель `rapier_head_on_regimes`: для зазоров 0.04, 0.35, 0.69, 0.73, 0.77, 0.86,
   0.99 от пути за шаг (v = 140) фиксирует `vx` на шаге удара и на следующем — таблица из раздела «Причина A» в `plan/stage_2.md`.
2. **Угол к углу.** Как в прежней редакции: две разведённые пары кубоидов, зазор по обеим осям меньше
   `prediction`, грани по касательной не перекрываются (блок 12.8×(большой) у проёма и корпус 12×9, раздел «Причина» выше).
   Зафиксировать через narrow phase Rapier, что точек контакта нет (или что скорость не меняется).
3. **Остановка.** Если Rapier на угловом случае ведёт себя не так, как в разделе «Причина» выше, — остановиться и сообщить.

### Шаг 5. Проверка на игре (локально, без коммита в игре) ✅ выполнен

Цель — убедиться, что правка лечит игру и ничего в ней не ломает. Файлы игры можно менять ТОЛЬКО временно, после
проверки откатить (`git -C /Users/dmitry/Sites/my/vimp-tanks checkout -- Cargo.toml Cargo.lock
core/src/client/predictor.rs`). Игра новых API не требует: правка меняет только поведение `obb_manifold`.

1. **Подключить локальный движок.** В КОРНЕВОЙ `/Users/dmitry/Sites/my/vimp-tanks/Cargo.toml` (корень workspace:
   `[patch]` в манифесте члена `core/` cargo игнорирует) дописать временно:
   ```toml
   [patch.crates-io]
   vimp-engine-core = { path = "../vimp/packages/engine/core" }
   ```
   Подключение видно по `Cargo.lock`: у `vimp-engine-core` пропадает `source`.
2. **Проверка.** `npm run core:test` в игре зелёный. Затем `npm run core:build:node`, `npm run build` —
   сценарии берут ядро из `dist/core-node`, без `build` прогон идёт на старом ядре. После этого
   `npm run sim:scenarios`: ожидается прежняя картина, красный только `terraces_backside.json`.
3. Откатить игру (см. выше) и пересобрать её (`npm run core:build:node && npm run build`), чтобы `dist/` и
   `core/pkg-node/` снова отвечали чистому коду.

Если на шаге 5.2 что-то падает — не подгонять пороги (они — определение «предсказание совпало», ослаблять их
нельзя), а остановиться и доложить пользователю с замерами.
