# Исходная постановка и разбор вариантов

Материал справочный: он объясняет, **почему** план выглядит так, и не
требуется для исполнения этапов. Индекс — [`README.md`](README.md).

## Диагноз

В `SoundManager.js` и стандартном Web Audio API — геометрическая ошибка
2D-звука.

1. **Плоскость без высоты (`Y = 0`).** Источник позиционируется как
   `sound.pos(dx, 0, dy)`, слушатель — в `(0, 0, 0)`. Если игрок бросает
   бомбу и отъезжает на 15–20 единиц вправо, вектор на источник — `(20, 0,
   0)`: для аудиодвижка источник находится строго под углом 90° прямо в
   правом ухе на микроскопическом расстоянии. HRTF-фильтр моментально глушит
   левый канал и применяет максимальную ушную фильтрацию (гребенчатая
   окраска).
2. **Бинарный разрыв.** Порог `MIN_SPATIAL_DISTANCE = 16` делает
   переключение дискретным: на 16 единицах звук монофонический по центру
   (паннера нет вовсе), на 17 — мгновенно прыгает в крайнее правое ухо с
   полной сменой тембра.

## Отвергнутые варианты

| Вариант | Почему нет |
| --- | --- |
| `equalpower` + плавная панорама на все мировые звуки | Убирает тембровые искажения HRTF, но полностью убивает различение «спереди/сзади» в игре с обзором 360° |
| Оставить HRTF, добавить только плавность | Разрыв «есть узел / нет узла» уходит, но остаточная окраска HRTF вблизи головы сохраняется: разница «под танком» / «рядом» уменьшится, но не исчезнет |
| Ближний радиус — непространственный, дальше HRTF | Сохраняет ровно тот же разрыв тембра, только переносит его на другую границу |
| Всё видимое на экране — непространственное | Теряется позиционирование перестрелок, взрывов и приближающихся врагов в пределах экрана — то, ради чего звук и нужен |

## Принятое решение

Архитектура «виртуальной высоты» (Virtual Elevation & Spread), как в Wwise,
FMOD и Unreal Audio Engine для 2D-игр:

```
                  [Слушатель / уши игрока] (0, H, 0)
                            |
                            |  H (virtualElevation)
                            |
   -------------------------+------------------------- плоскость игры (Y=0)
                      dx -> [Бомба] (dx, 0, dy)
```

- бомба прямо под танком → `(0, -H, 0)`: строго снизу по центру, одинаково
  в оба уха, без гребенчатого фильтра;
- танк отъехал на 20 единиц → `atan(20/180) ≈ 6.3°`: едва заметный мягкий
  сдвиг вправо;
- взрыв на краю экрана → выраженная локализация.

Плюс плавное рассеивание внутри радиуса корпуса игрока (`smoothstep`), что
исключает скачки фазы, и профиль проекции (`topDown` / `sideScroller` /
`cockpit`), чтобы движок оставался пригоден не только для вида сверху.

## Решения заказчика, зафиксированные до начала работы

1. **Где живёт настройка** — в клиентском конфиге плагина
   (`parts.sounds.spatial`) с дефолтами в
   `packages/engine/src/config/clientDefaults.js`.
   Не в `GameManifest`: манифест читают мастер (каталог игр, валидация
   архива) и лобби (форма комнаты, скачивание бандлов); мастер никогда не
   выполняет код плагина и ничего не знает о рендере и звуке. Геометрия
   панорамирования — сугубо внутриклиентская математика, в сетевом
   контракте лобби ей делать нечего.
   Не константами движка: игра с видом сбоку и игра с видом из кабины
   требуют разной проекции, и захардкоженный `topDown` лишил бы движок
   заявленной универсальности.
2. **Три профиля реализуются сразу.**
3. **Валидация двухуровневая:** статическое правило `vimp-contract` уровня
   `warn` (опечатка ловится до запуска браузера) + рантайм-санитаризация с
   `console.warn` и падением на дефолт (прод не должен ломать
   аудиоконтекст). Уровень именно `warn`: блок необязателен, его отсутствие
   не нарушение.
4. **Виртуальная высота учитывает зум камеры** через необязательный третий
   аргумент `setListenerPosition(x, y, scale = 1)`. При отдалении камеры
   картинка сжимается, и стереобаза обязана сжаться так же, иначе звук шире
   того, что видит глаз. `SoundManager` при этом не импортирует
   `CanvasManager` — масштаб приезжает числом.
5. **Охват** — три репозитория: `vimp-engine`, `vimp-tanks`, `vimp-snakes`.

## Отклонение от черновика заказчика

мировых координатах — обоснование в [`README.md`](README.md), раздел «Что НЕ
масштабируется зумом».
