## Цель

Объявить движковые дефолты пространственного звука так, чтобы игра, которая
ничего не объявляет, получила исправленный `topDown` автоматически.

## Файл

`packages/engine/src/config/clientDefaults.js`

Секции `parts` в файле сейчас нет. Добавить её между секцией
`interpolation` и секцией `modules`, в стиле соседних (комментарии
по-русски, объясняют *почему* число такое, а не что оно значит):

```javascript
  // ***** parts ***** //
  // Геометрия пространственного звука. Числа — в МИРОВЫХ единицах игры, не
  // в экранных пикселях: у игры с mapScale 0.3 и baseScale 5 мировая
  // единица впятеро меньше пикселя. Дефолты рассчитаны на масштаб 1:1,
  // игра со своим масштабом объявляет parts.sounds.spatial сама.
  parts: {
    sounds: {
      spatial: {
        // 'topDown' | 'sideScroller' | 'cockpit'
        mode: 'topDown',

        // высота ушей над плоскостью игры: она же ширина стереобазы.
        // Больше — мягче панорама вблизи игрока, меньше — агрессивнее
        // разделение по ушам. Ориентир: половина видимой высоты экрана
        virtualElevation: 180,

        // габарит игрока: всё, что звучит внутри этого радиуса, плавно
        // сводится к центру и распределяется поровну в оба уха
        innerRadius: 40,

        // только sideScroller: вклад вертикали в панораму. В платформере
        // высота на слух почти не читается
        verticalFactor: 0.2,

        // атрибуты PannerNode: ставятся один раз на Howl и покадрово не
        // пересчитываются. refDistance больше virtualElevation, иначе
        // источник под игроком тише, чем был до виртуальной высоты
        distanceModel: 'inverse',
        refDistance: 200,
        maxDistance: 1200,
        rolloffFactor: 0.9,
      },
    },
  },
```

## Обязательное условие

`panningModel` в дефолтах **не указывать**. Его подставляет профиль в
`SoundManager` (этап 2). Иначе `deepMerge` навсегда зафиксирует `HRTF`, и
смена `mode` на `sideScroller` не поменяет модель панорамирования — тихий
отказ ровно того класса, против которого написан этот план.

## Проверка совместимости (ничего править не нужно, просто убедиться)

- `packages/engine/src/lib/buildClientConfig.js:25-29` сливает
  `clientDefaults` с игровым клиентским конфигом через `deepMerge`:
  объекты сливаются рекурсивно, скаляры заменяются. Игровой каталог
  `parts.sounds.sounds` дефолтов не имеет и приезжает как есть.
- `packages/engine/src/client/main.js:381-384` берёт
  `data.parts.sounds || {}`, спредит его в `soundData` и перезаписывает
  `path`. После мержа `spatial` доезжает до `SoundManager.init` без единой
  правки в `main.js`.
