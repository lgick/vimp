# План: `create-vimp-game` — скаффолдер игровых плагинов VIMP

Индекс направления. Предварительное ТЗ —
[original-statement.md](original-statement.md); ниже — финальная версия,
переписанная под фактические контракты движка (`docs/ai/`), фикстуру
`miniGame` и опыт двух реальных плагинов.

## Контекст (что есть сейчас)

- Контракт плагина полностью описан: `docs/ai/` — 14 файлов, ~4300 строк,
  самодостаточная спецификация для нейросети (`01-architecture` …
  `13-debugging`). Это де-факто спецификация шаблона.
- Есть две реальные игры: `@vimp-games/tanks` (эталон, ~5.6 тыс. строк Rust
  + ~4.9 тыс. строк JS) и `vimp-street-fighters` — вторая игра, собранная
  нейросетью строго по `docs/ai/11-authoring-workflow.md`.
- Внутри движка живёт минимальный плагин-фикстура
  `packages/engine/tests/fixtures/miniGame/` (~1190 строк, JS-фейк вместо
  Rust-ядра) и контракт-тест `packages/engine/tests/fixtures/miniGame.contract.test.js`.
  Фикстура — фолбэк `pluginLoader` для `npm run sim`.
- Ошибок «по построению» ничто не ловит. `vimp-street-fighters` собран с
  `vimp-engine` в `dependencies` (должен быть `devDependencies`), с пином
  `vimp-engine-core = "0.1.0"` при актуальном `0.3.2`, с `edition = "2021"`
  и с параметром `'character'` вместо обязательного `'model'` в
  `src/config/auth.js` — последнее стоило отдельного баг-репорта и сорвало
  браузерный смоук.
- `docs/ai/10-pitfalls.md` перечисляет ~72 «тихих» инварианта; примерно
  30–35 из них проверяемы статически, по файлам конфигов и манифеста.

## Цель

1. `npm create vimp-game <name>` разворачивает **новую игру, а не копию
   tanks**: минимально-играбельный плагин, который сразу проходит
   `check:contract`, `core:test`, `test`, `build`, `sim` и запускает матч с
   ботами по `npm run dev`.
2. Тихие нарушения контракта ловятся машиной, а не браузерным смоуком: в
   движке появляется публикуемый валидатор `vimp-contract`, единый для
   шаблона, tanks и любой сторонней игры.
3. У нейросети, дописывающей игру, есть точка входа: сгенерированный
   `CLAUDE.md` с жёсткими правилами и командами проверки.

## Зафиксированные решения

1. **Валидатор контракта живёт в движке**, а не копируется в игру: новый
   `packages/engine/bin/vimp-contract.js` + `packages/engine/src/devtools/contract/`,
   рядом с `vimp-sim`. Один источник правды, эволюционирует вместе с
   `ENGINE_API_VERSION`, применим к уже существующим играм. Шаблон игры
   только вызывает его (`npm run check:contract`). Цена — `### Added` в
   `packages/engine/CHANGELOG.md`, minor-бамп npm-пакета `vimp-engine`.
2. **Шаблон — минимально-играбельный, без наследия tanks.** Ни один
   игровой конфиг, ассет, `models.js`/`weapons.js`, имя сущности или карта
   из tanks в шаблон не переносится. Наполнение пишется заново по
   `docs/ai/`; инфраструктурные файлы (vite/vitest/скрипты сборки) пишутся
   по спецификации `docs/ai/02-packaging.md`, tanks используется только как
   справка при неоднозначности спецификации.
3. **Состав минимальной игры** (рабочее имя внутри шаблона — «arena»,
   переименовывается токенами): две играющие команды + зрители, один класс
   актора, одно hitscan-оружие, одна карта, боты, вся графика — процедурная
   (PixiJS `Graphics` + bakers), **бинарных картинок в пакете нет**. Звук —
   две плейсхолдер-пары `webm`+`mp3`, синтезированные специально для
   шаблона.
4. **`--spec=game-spec.json` (генерация из JSON-ТЗ) — вне объёма v1.** Роль
   «наполнить игру» закрывают сгенерированный `CLAUDE.md` и интервью
   `docs/ai/12-questionnaire.md`.
5. **`create-vimp-game` в `npm run release` не заводится в v1** — публикуется
   вручную (`npm publish -w create-vimp-game`) со своим `CHANGELOG.md`.
   Причина: `scripts/release/*` знает ровно два артефакта (крейт + движок), а
   игры ищет вне воркспейса по `npm link`; третий тип артефакта — отдельная
   работа.
6. **Пины версий не хардкодятся в шаблоне.** `vimp-engine` и
   `vimp-engine-core` подставляются генератором из фактических
   `packages/engine/package.json` и `packages/engine/core/Cargo.toml`
   (сегодня `0.9.0` и `0.3.2`). Это лечит болезнь street-fighters.
7. **Защита шаблона от дрейфа — тяжёлый E2E в CI**: отдельный job
   скаффолдит игру во временную папку и прогоняет полный цикл (cargo +
   wasm-pack + build + sim). В локальный `npm test` не входит.
8. **Метод разработки шаблона**: файлы шаблона содержат `{{ТОКЕНЫ}}` и сами
   по себе не собираются, поэтому любая проверка идёт через генерацию во
   временную папку. Цикл на всех этапах 3–5 один и тот же:
   `node packages/create-vimp-game/bin/create-vimp-game.js <tmp> --yes
   --engine-path … --core-path …` → сборка → `vimp-contract` → `sim`.

## Критерии готовности направления

- [x] `npx eslint .` и `npm test` в репозитории движка зелёные.
- [x] `npm run core:test` зелёный (крейт движка не тронут).
- [x] `node packages/engine/bin/vimp-contract.js --game <tanks>` — зелёный;
      на `vimp-street-fighters` ловит `A1` (`vimp-engine` в `dependencies`),
      `A5` (пин крейта `0.1`) и `E2` (картинки карт не в `dist/img/`);
      четвёртое отклонение (`character` вместо `model`) в том репозитории
      уже исправлено, правило `C10` его стережёт.
- [x] `npm create vimp-game my-game --yes` разворачивает проект, где
      `core:build`, `check:contract`, `build`, `test`, `sim` завершаются с
      кодом `0` (проверено `npm run test:scaffold`, этап 6).
- [ ] `npm run dev` в сгенерированной игре даёт матч с ботами в браузере
      (ручной смоук).
- [x] В сгенерированной игре нет ни одного файла, конфига или ассета,
      перенесённого из tanks.
- [ ] Проектный `CLAUDE.md` движка остался в пределах 1000 токенов.
