# Кодревью коммита 4c3bf30 (второй раунд) + план правок

## Контекст

Коммит `4c3bf30` («review», ветка `standalone-sdk`, в `origin` не отправлен)
закрывает [review.md](review.md) — Этап R: блокеры P1-1…P1-4, значимые
P2-1…P2-4, мелкие P3-1…P3-6. Ревьюилось состояние кода целиком (не только
диффы) в местах правки и их окружении.

Прогнано в ходе ревью: `npx eslint .` — чисто; `npm test` — **122 файла /
1212 тестов** зелёные; `npm run build:app` — собрался, CSP-хэш importmap
совпал, правила `style.css` доехали в бандл в правильном виде
(`body>*,.vimp-shell>*{display:none}body>.vimp-shell{display:revert}`).

**Итог: все восемь заявленных правок сделаны и механизм каждой проверен.**
Найдены **2 значимых** проблемы (обе — в новом контуре, обе создают ловушку
ровно на документированном пути), **4 мелких** и 1 косметическая. Блокеров нет.

## Часть 1. Значимые находки

### R2-1. `style.css` в SDK гасит страницу игры целиком, а совет в доках для вложенного контейнера не работает ✅ выполнен

**Факт.** Правило `body > * { display: none }`
(`packages/engine/src/client/style.css:24-27`) сохранено, а `style.css`
импортирует `client/main.js:1` — то есть в репозитории игры оно применяется к
странице игры. Скрываются **все** элементы первого уровня, а не только экраны
движка: собственный заголовок dev-страницы, кнопки, любая её разметка. Плюс
`html, body { width/height: 100% }` и `body { background: #000; color: #ccc;
font-family: … }` — SDK переопределяет базовую типографику страницы.

**Ловушка в доках.** Для вложенного контейнера
(`body > #wrap > #game.vimp-shell`) диагноз в доках неверен: сам контейнер не
попадает ни под одно скрывающее правило (`body > *` его не выбирает, а
`.vimp-shell > *` выбирает его *детей*) — скрыт `#wrap` правилом `body > *`.
Поэтому совет «задайте контейнеру собственный `display`, селектор по id
перебивает правило» **не помогает**: помогает `display` у предка первого
уровня либо подъём контейнера на уровень `body`. Затронуты
`docs/en/client.md:99-109`, `docs/ru/client.md:39`,
`docs/en/standalone.md:135-141` и раздел Troubleshooting (`:194-197`),
`docs/ru/standalone.md` — те же места.

**Решение** (движковое, а не документационное). `body > *` нужен ровно для
одного — чтобы pug-разметка не мигнула до исполнения JS на **нашей** странице.
После `ensureGameShell(document.body)` класс `vimp-shell` попадает на `body`, и
`.vimp-shell > *` тождественно `body > *`. Значит:

1. FOUC-правило вернуть в инлайн-`<style>` `packages/engine/index.html` (CSP
   уже разрешает: `style-src 'self' 'unsafe-inline'`,
   `src/config/master.js:98`) — с комментарием, что после `ensureGameShell`
   его дублирует класс-форма.
2. В `style.css` оставить только `.vimp-shell > * { display: none }`; правило
   `body > .vimp-shell { display: revert }` тогда не нужно вовсе — контейнер
   любого уровня вложенности виден без правок страницы.
3. Доки (обе локали, `client.md` + `standalone.md`): убрать неверный совет,
   описать реальную схему; отдельной строкой сказать, что показ экранов идёт
   инлайновым `display` по `initIdList` (`main.js:448-454`) — то есть CSS игры
   для полотен и своих элементов должен целиться по id, иначе
   `.vimp-shell > *` (0-1-0) перебьёт правило вида `canvas { display: block }`.
4. Тест: `tests/client/gameShell.test.js` — статикой сверить, что FOUC-правило
   в `index.html` и класс-форма в `style.css` не разъехались (happy-dom каскад
   не считает, поэтому только статика; см. R2-6).

**Альтернатива по минимуму** (если правило решено не двигать): пункты 3 и 4 —
обязательны в любом случае, плюс в `standalone.md` явно предупредить, что
страница-хост теряет свои элементы первого уровня и базовую типографику.

### R2-2. Таймаут хендшейка 30 с считает время, которое игрок тратит на форму → dedicated уходит в петлю перезагрузок ✅ выполнен

**Симптом.** Игрок, замешкавшийся с вводом ника (или зашедший на слабой
машине/медленном канале), получает `close(4008, 'handshakeTimeout')`, дальше
`handleDisconnect` показывает общее «The match is over…» и через 3 с делает
`location.reload()` (`main.js:1229-1234`, в `dedicated` перезагрузка включена).
После перезагрузки отсчёт начинается заново — цикл не разрывается сам.

**Почему 30 с мало.** `hasParticipant` становится true только после
`AUTH_RESPONSE` (`PortMachine.js:239`), а `AUTH_DATA` уходит клиенту лишь
после его `CONFIG_READY`, который клиент отправляет **после**
`Promise.all(initPromises)` — `app.init()` на каждое полотно плюс
`assetProvider.bakeAll` (`main.js:317-372`). То есть в 30 секунд уложены:
инициализация WebGL и запекание ассетов + рендер формы + **ввод ника
человеком**. Причина закрытия при этом уходит кодом, без `TECH_INFORM`, —
игрок видит не «вы слишком долго», а «матч закончен».

**Решение** (`src/dedicated/main.js`): поднять `HANDSHAKE_TIMEOUT` до 120–180 с
(slowloris это по-прежнему ловит) **или** снимать/перезаводить guard на первом
кадре от клиента (`CONFIG_READY` доказывает, что это живой клиент, а не
висящий сокет). Числовое значение обновить в таблице лимитов
`docs/en|ru/dedicated.md`. Отдельно стоит доставлять причину через
`socketManager.close`, чтобы игрок видел внятный текст.

## Release impact

Артефакт — npm `vimp-engine` (правки в `src/client/**`, `src/host/**`,
`src/standalone/**` — всё внутри `files`). Уровень `[Unreleased]` остаётся
**minor** (`### Added`; добавленный `### Security` — patch, minor его
перекрывает). Крейт `vimp-engine-core` не затронут, `ENGINE_API_VERSION` не
менялся → репозиторий игры следовать не обязан. `version` не правим —
публикует разработчик через `npm run release`.
