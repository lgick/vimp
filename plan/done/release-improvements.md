# Улучшения `npm run release`

## Контекст

Аудит релиз-скрипта (`scripts/release*`) 2026-09-25. Планировщик работает
(173 теста зелёные, dry-run с обеими играми — «публиковать нечего»), версии
движка/крейта/скаффолдера/игр совпадают с реестрами. Найдены дефекты:

- существующий тег переиспользуется молча, даже если стоит не на HEAD, а
  повторный пуш уже существующего тега CI не перезапускает — так появилась
  дыра `@vimp-games/tanks@0.22.1` (тег на коммите с version 0.22.0);
- `release.yml` (движок, игры) не сверяет версию тега с версией в файле;
- Ctrl-C на вопросе после снятия линков, скорее всего, не возвращает линки
  (readline перехватывает SIGINT);
- политика «крейт → игры обязательно, minor» расходится с CLAUDE.md
  («lets it follow, never forces it»). Решение: игры — по желанию, patch;
- мелочи: `git fetch` после `collect()`, неточные сообщения, мёртвый код,
  устаревшая строка в publishing.md, дыры в CHANGELOG вынужденных релизов.

## Этап 1. Критичные ✅ выполнен

1. Теги: чистая функция `tagAction({ local, remote, head })` → create / push /
   skip / retrigger (тег на remote на HEAD, версии в реестре нет) / move (тег
   не на HEAD — спросить, под `--yes` отказ). Заменяет `tag()` + `git push
   origin <tag>` в шагах A1–A3 и B. Тесты на функцию и на шаги.
2. `release.yml` движка (3 джоба) и обеих игр: шаг «Verify tag matches
   version».
3. ~~`ui.js`: проброс SIGINT~~ — проверено на псевдотерминале: в Node 26
   `readline/promises` на Ctrl-C отклоняет вопрос (`AbortError`), `finally`
   возвращает линки. Дефекта нет, правка не нужна.

## Этап 2. Политика игр ✅ выполнен

1. `plan.js`: крейт/движок/отставший пин больше не делают игру `required`;
   такой сигнал — `optional` с причиной, уровень patch. Собственные сигналы
   игры (ahead / коммиты после тега) — как раньше.
2. `release.js`: optional-игра спрашивается отдельно (по умолчанию «нет»);
   под `--yes` публикуется, только если передана явным `--game`.
3. Убрать мёртвое `engineApiChanged`/`strictlyLast`/`engineApiDiffers`.

## Этап 3. Авто-запись в CHANGELOG ✅ выполнен

`changelog.js`: `withFallbackEntry(text, entry)` — пустой `[Unreleased]`
вынужденного релиза получает `### Changed` + строку (движок: новый
`core/Cargo.toml`; скаффолдер: новые пины; игра: пересборка против
крейта/движка). Непустой журнал не трогается.

## Этап 4. Мелочи и чистка ✅ выполнен

- `git fetch` до `collect()`; честная причина для `unpushed`;
- прод: убрать повторный пуш тегов (теги уже пушат шаги) и слово «теги» в
  остатке; `--relink` без игр — «нечего привязывать»;
- удалить `isLinked`, `tagFor`, лишний `readFile` в release.js.

## Этап 5. Документация ✅ выполнен

`docs/en|ru/publishing.md`: политика игр, авто-записи, теги/перезапуск CI,
guard в CI, удалить «crate bump has to be repeated by hand».

## Проверка

`npx eslint .`, `npm test`, `node scripts/release.js --dry-run --yes --game
../vimp-tanks --game ../vimp-snakes`. Ctrl-C на вопросе — вручную.

## Этап 6. Доработки по код-ревью ✅ выполнен

- `releaseTag`: retrigger без локального тега сначала ставит его; вопрос о
  перевыставлении — «нет» по умолчанию;
- `unpushedTags` отсекает теги, уже лежащие в `origin`; прод без
  незапушенных коммитов не зовёт пушить; параметр `tags` удалён;
- `release.yml`: версия через `GITHUB_ENV`, проверка версии тега — сразу
  после checkout (`jq`);
- `buildVersions` после вопросов о версиях вместо `syncBuildVersions`;
  `decide()` больше не отдаёт устаревшие `crateVersion/engineVersion`;
- `rebuildEntry` называет только то, что реально сменилось;
- вопрос «выпустить игру?» — один, в `selectGames`; `--follow-games` для
  `--yes`; невыпущенные игры — строгий sim `latest` на шаге прода при деплое.
