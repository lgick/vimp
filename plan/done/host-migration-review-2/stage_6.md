## Зачем

`client/main.js` исполняется при импорте и в юнит-тесты не поднимается
(решение этапа 14 прошлого плана). Модули `client/session/*` покрыты
тестами по отдельности, а их связи — поздние геттеры
(`getHandoff`/`getPromotion`/`getGuest`), общий `roomCtx`, порядок
`bind()` в `main.js` — проверит только живой прогон. Ни один этап обоих
планов ревью вручную не прогонялся; исходный план
`plan/host-migration/` ждёт того же smoke (п. 11.3 и ручные проверки
этапов 8 и 10 — `plan/host-migration/stage_11.md`).

## Подготовка

Dev-контур — `docs/en/getting-started.md`:

1. Плагины `@vimp-games/tanks` и `@vimp-games/snakes` слинкованы в обе
   стороны (`npm link`; dev-мастер отдаёт исходники плагина через `/@fs/`),
   ядра игр собраны (`npm run core:build` в репозитории игры).
2. `npm run dev:auth` (auth на Postgres, миграции — `npm run
auth:db:migrate`) и `npm run dev` (мастер, `https://localhost:3002`,
   нужны mkcert-сертификаты).
3. Три профиля Chrome + Firefox, каждый залогинен **своим** аккаунтом
   через закладку
   `http://localhost:3010/dev/login?nick=P<N>&returnUrl=https://localhost:3002/`
   (разные аккаунты нужны для голосования и отчётов о недоступном хосте —
   они считаются по пользователям).
4. В каждой вкладке открыта консоль (фильтр `[worker]`, `[promotion]`,
   `[handoff]`, `[standby]`, `[session]`).
