## Общие правила для каждого этапа

Репозиторий: `/Users/dmitry/Sites/my/vimp` (пути ниже — от его корня,
если не сказано иное). Исходники движка — `packages/engine/src/`, тесты —
`tests/` (зеркально `packages/engine/src/`, например
`packages/engine/src/master/SignalingServer.js` →
`tests/master/SignalingServer.test.js`; модули `client/session/*` →
`tests/client/session/*`, общие фейки — `tests/client/session/sessionFakes.js`).

1. **Тест первым.** Исправление начинается с теста, который
   воспроизводит ошибку и падает на текущем коде; после правки он зелёный.
   Vitest + happy-dom, тесты не колокейтятся с кодом.
2. **Конец этапа — зелёный прогон:**
   `npx prettier --write <изменённые файлы>`, `npx eslint .`,
   `npx vitest run --reporter=dot`. Rust не трогается.
3. **Документация в том же изменении:** страница `docs/en/<page>.md` и её
   зеркало `docs/ru/<page>.md` (таблица «область → страница» в
   `CLAUDE.md`: `src/master/` → `master.md`, `src/host/` → `host.md`,
   `src/client/` → `client.md`, протокол → `network.md`, `src/config/*` →
   `configuration.md`). В `docs/ru/` абзац записан одной строкой — правка
   повторяет смысл английской, а не её переносы.
4. **CHANGELOG.** Вся миграция хоста ещё не выпущена (`## [Unreleased]`
   в `packages/engine/CHANGELOG.md`, уже есть `### ⚠️ Breaking` → релиз
   minor). Правки этого плана уточняют невыпущенные возможности, поэтому
   **правится текст существующих записей `[Unreleased]`**, новые
   подзаголовки и записи не заводятся. Тесты, рефакторинг, комментарии и
   `docs/` — не записи. Уровень релиза не меняется.
5. **Протоколы — только добавление.** Порты, коды закрытия, имена
   сообщений и полей не меняются; новое — только добавляется (новая
   причина `voteRejected` допустима: клиент показывает неизвестную причину
   общим `HOST_VOTE_UNAVAILABLE`). `contract/surface.json` не меняется;
   если шаг этого требует — остановиться и обсудить с разработчиком.
6. **Решения.** Всё, что влияет на наблюдаемое поведение и не
   зафиксировано в файле этапа, согласуется с разработчиком **до** кода
   (вопрос — на русском, варианты, рекомендуемый помечен). Пункты
   «⚠️ подтвердить» согласуются перед началом этапа; согласованное
   вписывается в файл этапа (раздел «Согласовано») до правки кода.
7. **Без коммитов и без правки `version`.** Всё остаётся в рабочем дереве.
   Файлы с префиксом `_` не читать и не трогать.
8. **Release impact в отчёте этапа:** какой артефакт тронут (npm
   `vimp-engine`, крейт, `create-vimp-game`, auth), какой бамп следует из
   подзаголовка changelog, нужно ли что-то в репозиториях игр, какие
   проверки прошли.
9. UI-строки движка — на английском. Комментарии в коде — по-русски, как
   во всём движке; объясняют «почему», коротко.
10. Числовые пороги — в конфиге (`packages/engine/src/config/lobby.js` —
    клиент, `config/master.js` — мастер); каждый изменённый ключ описан в
    `docs/{en,ru}/configuration.md`.
