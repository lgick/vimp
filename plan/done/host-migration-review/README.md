## Общие правила для каждого этапа

Репозиторий: `/Users/dmitry/Sites/my/vimp` (пути ниже — от его корня,
если не сказано иное). Исходники движка — `packages/engine/src/`, тесты —
`tests/` (зеркально `packages/engine/src/`, например
`packages/engine/src/master/SignalingServer.js` →
`tests/master/SignalingServer.test.js`).

1. **Тест первым.** Исправление ошибки начинается с теста, который
   воспроизводит её и падает на текущем коде; после правки он зелёный.
   Vitest + happy-dom, тесты не колокейтятся с кодом.
2. **Конец этапа — зелёный прогон:**
   `npx prettier --write <изменённые файлы>`, `npx eslint .`,
   `npx vitest run --reporter=dot`. Rust в этом плане не трогается.
3. **Документация в том же изменении:** страница `docs/en/<page>.md` и её
   зеркало `docs/ru/<page>.md` (таблица «область → страница» в
   `CLAUDE.md`: `src/master/` → `master.md`, `src/host/` → `host.md`,
   `src/client/` → `client.md`, протокол/порты → `network.md`,
   `src/config/*` → `configuration.md`). Изменения контракта плагина —
   ещё и в `docs/ai/`.
4. **CHANGELOG.** Вся миграция хоста ещё не выпущена (`## [Unreleased]`
   в `packages/engine/CHANGELOG.md`, уже есть `### ⚠️ Breaking` → релиз
   minor). Правки этого плана уточняют невыпущенные возможности, поэтому
   **правится текст существующих записей `[Unreleased]`**, новые
   `### Fixed` не заводятся (правило `CLAUDE.md`: отдельная запись нужна
   только для уточнения уже выпущенного). Тесты, рефакторинг и `docs/` —
   не записи. Уровень релиза не меняется.
5. **Протоколы — только добавление.** Порты (`config/wsports.js`) и коды
   закрытия (`config/closeCodes.js`) не трогаются. Новые сообщения мастера
   и поля — добавляются, старые имена и алиасы остаются. Протокол главный
   поток ↔ Worker: новый Worker обязан понимать сообщения старого главного
   потока (страница, загруженная до деплоя, поднимает Worker по свежему
   манифесту) — новые типы только добавляются. `contract/surface.json`
   не меняется ни в одном этапе; если шаг этого требует — остановиться и
   обсудить с разработчиком.
6. **Решения.** Всё, что влияет на наблюдаемое поведение и не зафиксировано
   в файле этапа, согласуется с разработчиком **до** кода (вопрос — на
   русском, варианты, рекомендуемый помечен). Пункты с пометкой
   «⚠️ подтвердить» согласуются перед началом этапа; согласованное
   вписывается в файл этапа до правки кода.
7. **Без коммитов и без правки `version`.** Всё остаётся в рабочем дереве.
   Файлы с префиксом `_` не читать и не трогать.
8. **Release impact в отчёте этапа:** какой артефакт тронут (npm
   `vimp-engine`, крейт, `create-vimp-game`, auth), какой бамп следует из
   подзаголовка changelog, нужно ли что-то в репозиториях игр, какие
   проверки прошли.
9. UI-строки движка — на английском. Комментарии в коде — по-русски, как
   во всём движке; объясняют «почему», коротко.
10. Числовые пороги — в конфиге: клиент — `packages/engine/src/config/lobby.js`,
    мастер — `packages/engine/src/config/master.js`, Worker —
    `packages/engine/src/config/hostDefaults.js`; каждый новый ключ описан
    в `docs/{en,ru}/configuration.md`.
