## Ответ на задачу 3 (кратко)

Зайти под ником **уже зарегистрированного** админа нельзя: ник глобально
уникален без учёта регистра, переименования не существует, сравнение со
списком идёт в нижнем регистре с обеих сторон. Дыра в другом — админские
права привязаны к *строке ника*, а не к личности: **свободный** ник из
`VIMP_ADMIN_NICKS` (новая БД, ник добавлен в список до первого входа
человека, опечатка в списке) достаётся первому, кто под ним
зарегистрируется, вместе с ролью `admin`. Разбор — F12 в
[review.md](review.md), закрытие — [stage_4.md](stage_4.md).

## Release impact (по `CLAUDE.md`)

- **Этап 1** — только `.github/`: в публикуемые артефакты не входит,
  записи в changelog не требует.
- **Этап 2** — npm-пакет `vimp-engine` (роут мастера + клиент лобби) и
  auth-сервис (отдельный деплой-артефакт, миграций не требует). Запись
  в `packages/engine/CHANGELOG.md` → `### Added`, уровень **minor**.
- **Этап 3** — `vimp-engine`, `### Fixed`, **patch**.
- **Этап 4** — auth-сервис + документация. Если выбран вариант с новой
  переменной окружения (`VIMP_ADMIN_IDENTITIES`) — это `### Added` в
  `packages/engine/CHANGELOG.md` **только** если меняется движковая
  часть; чисто auth-правка в движковый changelog не попадает, но
  `docs/{en,ru}/auth.md` и `deployment.md` обязаны обновиться.
- **Этап 5** — `vimp-engine`, `### Fixed` (+ `### Changed`, если
  убираются `homepage`/`description` из `fetchPackageMeta`), **patch**.
- Крейт `vimp-engine-core` не затрагивается ни одним этапом —
  репозиторию игры следовать не за чем.
- `packages/engine/contract/surface.json` не трогается, `ENGINE_API_VERSION`
  остаётся 4.
- Версии в `package.json` не править, `npm run release` не запускать.
