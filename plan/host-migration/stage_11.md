## 11.2. Порядок выката (записать в `docs/{en,ru}/deployment.md`) ✅ выполнен

0. До деплоя: завести секрет `VIMP_ROOM_SECRET_KEY` (≥ 32 случайных
   байт) в GitHub и пробросить в окружение мастера (этап 2) — без него
   production-мастер не стартует. Ключ не менять без нужды: смена ключа
   делает невозможным `reclaim_host` живых комнат после следующего
   рестарта мастера.
1. Мастер + клиент (push в `main` деплоит мастер): мастер перестаёт
   ходить в `/host-rating`, понимает старые поля (`hostId`, `hostSecret`,
   `name`) от страниц, загруженных до деплоя.
2. Затем auth-сервис с миграциями `015_drop_host_rating.sql` и
   `016_rank_write_idempotency.sql` (`npm run auth:db:migrate`). Обратный
   порядок сломает старый мастер (он ещё зовёт удалённые маршруты).
   `deploy.yml` катит мастер и auth на один push параллельно — решение
   разработчика (2026-10-03): **два пуша**, `deploy.yml` не трогаем. Первый
   push — с временно очищенной переменной `AUTH_SERVER_IP` (job auth
   пропускается); после деплоя мастеров вернуть переменную и сделать
   второй push.
3. Игры: `@vimp-games/tanks` и `@vimp-games/snakes` с
   `migration.midRound: true` — публикуются разработчиком после движка; до
   их выхода комнаты этих игр мигрируют в мягком режиме.
