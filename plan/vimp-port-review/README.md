# Правки по итогам кодревью переноса tank-battle → vimp-tanks / vimp-engine

## Контекст

Ревью работы по плану `tank-battle/plan/done/vimp-port/README.md` (этапы 1–11
и 8a): движок — `git diff 81a1b85 HEAD` (36 файлов, +2029/−91), плагин
`vimp-tanks` — `git diff 8817036~1 HEAD` (54 файла, +5996/−476). Прочитаны все
изменённые файлы кода обоих репозиториев; тесты в ходе ревью не запускались.

Перенос выполнен качественно: наследование JS корректно переложено на
композицию (`PredictedSet` + трейт `PredictedBodies`), дисциплина «двух
фреймов» (симуляционный ↔ рендерный) проведена до конца и объяснена в каждой
точке потребления, граница «движок ↔ игра» не размыта (`PredictedRow` —
единственное, что движок узнал про игровые строки, и ширину он приводит к
схеме сам). Найденное ниже — не переделка, а восемь точечных долгов.

Задача этого плана: закрыть их, не меняя поведения игры.

## Что проверено и правки НЕ требует

Три места выглядят дефектами, но ими не являются — зафиксировано, чтобы к ним
не возвращаться:

1. **`ENGINE_API_VERSION` остался 3 при `SNAPSHOT_FORMAT_VERSION` 5.**
   Обоснование в `packages/engine/CHANGELOG.md` (0.12.0) верное: пакер
   (`core/src/snapshot.rs`) и распаковщик (`core/src/client/unpack.rs`)
   статически линкуются в один и тот же wasm плагина, поэтому раскладка кадра
   не может разъехаться между сторонами из-за версии движка; `optionalFrom`
   аддитивен, старая схема валидна, старый манифест (`GameCatalog.js:59`)
   не становится незагружаемым. В отчёте по этапу 7 сказано
   «`ENGINE_API_VERSION = 4`» — расхождение отчёта с кодом, право за кодом.
2. **Отсутствие `texture: false, baseTexture: false` в `destroy()` эффектов.**
   В Pixi v8 `Container.destroy({ children: true })` уничтожает текстуру
   ребёнка только при явном `options.texture === true`, `baseTexture` — легаси
   v7. Запечённые на сессию текстуры не страдают.
3. **`impulseMagnitude: 5000 → 7500000`.** В `src/data/weapons.js` hitscan
   ровно один (`w1`, `range: 1500`), пересчёт `5000·1500` корректен; `w2` —
   `explosive`, через `process_hitscan` его импульс не проходит.
