# План: замена авторизации — гость с ником от системы, passkey, Turnstile

Текущая авторизация (GitHub OAuth → pending-токен → выбор ника → identity
JWT на 4 часа, логин-гейт перед лобби) **удаляется целиком** и заменяется
новой по правилам разработчика (2026-10-06/07). Отчёт о старой схеме и
находка F10/D3 (истечение токена посреди матча) — в
`plan/done/host-migration-review/review.md`; D3 этим планом снимается
(вечная сессия + тихое продление JWT).

> **Как исполнять.** Перед этапом читать только этот файл и файл этапа.
> Каждый этап самодостаточен: контекст, файлы, шаги, тесты, доки,
> критерии. Коммитов не делать, `version` не трогать, файлы с префиксом
> `_` не читать и не трогать. Этап помечается «✅ выполнен» в своём
> заголовке и в таблице ниже. **Этап 0 — до любого кода.**

## Правила новой авторизации (от разработчика, дословно по смыслу)

**Авторизация**

- При первом входе авторизация не нужна и не обязательна.
- Авторизация — через WebAuthn / Passkeys, в лобби.
- Авторизация без срока действия: заново авторизоваться не нужно.
- При бездействии учётная запись игрока удаляется из БД через 30 дней.
- Ранг и скиллы без авторизации в БД не сохраняются.
- Первый визит и игрок без авторизации — **никаких данных в БД**; аккаунт
  в БД создаётся только после авторизации (защита от засева БД ботами).

**Ник**

- Уникальный ник генерируется системой автоматически при визите, без
  нажатия кнопок.
- Сменить ник без авторизации нельзя.
- Ник уникален; сменить можно по текущим правилам VIMP (`isValidNick`,
  уникальность без учёта регистра).
- Ник нельзя поменять в играх — убрать из игр смену ника.

**Капча** — Cloudflare Turnstile: при смене ника и перед тем, как гость
создаёт сервер или входит на сервер (бот не должен создавать серверы и
заходить на них).

## Принятые решения (согласовано 2026-10-07)

| #   | Вопрос                 | Решение                                                                                                                                                                                                                                                           |
| --- | ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Р1  | Объём                  | Один план: удаление старой авторизации + новая. D1 и D2 — отдельные планы (`plan/engine-chat-default-texts.md`, `plan/host-disconnect-grace.md`)                                                                                                                  |
| Р2  | Текущие аккаунты       | **Чистый старт**: миграция БД удаляет всех пользователей и их ranks/states/леджер (CASCADE); игры реестра остаются, авторство и модератор обнуляются (`ON DELETE SET NULL`)                                                                                       |
| Р3  | Домен passkey (rpId)   | Общий родительский домен лобби и auth из конфига auth (`VIMP_AUTH_WEBAUTHN_RP_ID`, прод — `vimp.lgick.space`), церемония прямо в лобби. Мастер на домене вне rpId показывает «вход по passkey недоступен на этом сервере», гостевой режим там работает            |
| Р4  | Токены                 | **Вечная сессия устройства + короткий identity-JWT.** Браузер хранит секрет сессии; по нему клиент молча получает JWT (4 ч), мастер и хост проверяют JWT по JWKS, как сейчас. Хосту — новый клиентский порт `TOKEN_REFRESH` (11), чтобы долгий матч не терял очки |
| Р5  | Админы                 | По id аккаунта: `VIMP_ADMIN_USER_IDS=17,42` (только аккаунты с passkey). `VIMP_ADMIN_NICKS` и `VIMP_ADMIN_IDENTITIES` удаляются                                                                                                                                   |
| Р6  | Исключения из удаления | Админы (`VIMP_ADMIN_USER_IDS`) по неактивности **не** удаляются. Авторы игр — удаляются (авторство обнуляется)                                                                                                                                                    |
| Р7  | Где Turnstile          | Смена ника; гость перед созданием сервера и входом на сервер. **Не** при визите/выдаче ника, **не** при регистрации и входе по passkey                                                                                                                            |
| Р8  | Гость в БД             | Гостя в БД нет. Гостевая личность — подписанный auth-сервисом токен без строки в БД; единственное касание БД — счётчик `SEQUENCE` для уникального ника (не данные игрока)                                                                                         |

## Целевая архитектура (кратко)

```
Браузер лобби (vimp.lgick.space)              auth (auth.vimp.lgick.space)
───────────────────────────────              ────────────────────────────
первый визит ── POST /guest ───────────────►  nextval(guest_nick_seq) → ник
             ◄─ { session: 'g_…', token }     (гостя в БД нет; session —
                                              HMAC-подписанный гостевой токен)
каждые ~3 ч ── POST /token {session} ──────►  гость: проверка подписи
             ◄─ { token (JWT 4 ч) }           участник: строка sessions по
                                              sha256(секрета), last_active_at
создать/войти (гость) ── Turnstile ─────────►  POST /guest/verify → hvUntil в
                                              гостевой сессии и в JWT
«Save progress» ── WebAuthn create ─────────►  POST /passkey/register/* →
                                              users + webauthn_credentials +
             ◄─ { session: 'm_…', token }     sessions (аккаунт появляется)
«Sign in with passkey» ── WebAuthn get ─────►  POST /passkey/login/*
«Change nick» ── Turnstile + POST /nick ────►  только участник (passkey)

identity-JWT (RS256, /jwks): sub, nick, kind: 'guest'|'member', role,
hvUntil? (гость прошёл Turnstile), exp 4 ч. Гость: sub = '-<gid>'
(отрицательный — id участников положительные, мастеру не нужен новый тип).

Мастер: register_host (новая комната) и join_room (новое членство)
требуют участника или гостя с hvUntil > now; admin-роуты и реестр игр —
только участник. Хост: вход в матч (AUTH_RESPONSE) — то же правило
(кроме собственного игрока хоста); rank/state пишутся только участникам;
свежий JWT приезжает портом TOKEN_REFRESH. Суточная задача auth удаляет
аккаунты без активности 30 дней (кроме админов).
```

## Общие правила для каждого этапа

Репозиторий: `/Users/dmitry/Sites/my/vimp` (пути — от корня). Движок —
`packages/engine/src/`, тесты движка — `tests/` (зеркально `src/`),

## Release impact (сводка)

- **npm `vimp-engine`** — `### ⚠️ Breaking` + `### Migration` (мастер и
  хост отвергают identity-токены без `kind`, то есть токены старого
  auth-сервиса: движок требует auth-сервис той же версии) → minor.
  Плюс `### Added` (порт `TOKEN_REFRESH`, гостевой вход, passkey) и
  `### Changed` (смена ника в игре отключена).
- **npm `create-vimp-game`** — шаблон без `/name` → `### Removed` (patch).
- **auth-сервис** — несовместимое API (OAuth удалён), миграция БД 017 с
  чистым стартом, новые переменные окружения; деплоится тем же пушем.
- **`../vimp-tanks`, `../vimp-snakes`** — убрать `/name` (этап 7), релиз
  игр по их правилам; старые релизы игр продолжают работать (команда
  становится пустой, ник не меняется).
- **Крейт `vimp-engine-core`** — не затрагивается.
