# План: игры VIMP не устаревают

Индекс этапов. Читать перед любым этапом — здесь инварианты, которым
подчиняются все шесть.

## Контекст

Сегодня плагинная совместимость проверяется строгим равенством:
`manifest.engineApi !== ENGINE_API_VERSION` →
`packages/engine/src/lib/gamePlugin.js:34`. Гейт стоит на четырёх входах:

| Вход | Точка | Форма отказа |
| --- | --- | --- |
| Мастер (каталог) | `src/master/GameCatalog.js:60` | `console.warn` + `continue` — игра молча исчезает из `manifestList` |
| Dedicated / `vimp-sim` / InlineHostBridge | `src/lib/loadGamePackage.js:35` | `throw` на старте процесса |
| Браузерный клиент | `src/lib/gamePlugin.js:126` | `throw` до динамического импорта |
| Standalone SDK | `src/standalone/index.js:60-61` | `throw` на обеих половинах |

Следствие: **после каждого бампа `ENGINE_API_VERSION` каждая игра обязана
пересобраться и перепубликоваться**. При двух своих играх это неудобство,
при ста играх независимых разработчиков — гарантированное вымирание
каталога.

Хуже того, половина исторических бампов была не нужна. `v3 → v4`
(`src/config/opcodes.js:12-14`) добавил порт `ACCOLADES_DATA: 18`
(`src/config/wsports.js:24`), отправку в `host/meta/SocketManager.js:348`,
приём в `client/main.js:654` и пятый сервис клиентского пула
(`client/main.js:386`, реестр — `devtools/contract/rules/c4-component-dependencies.js:16`).
Всё это — код движка. Игра под v3 не объявляет `accolades`, не подписана на
порт 18 и работала бы на v4 без единой правки. Её всё равно выкинуло.

**Цель:** снять с игр срок годности. Не продлить окно поддержки, а отнять у
движка саму способность ломать плагинную поверхность, после чего гейт по
версии удаляется за ненадобностью.

Постановка задачи и обоснование радикального варианта —
[`original-statement.md`](original-statement.md).

## Инварианты плана

Им подчиняется каждый этап; нарушение любого — повод отклонить правку.

**И1. Ничто не удаляется и не переименовывается.** Любое имя, которое игра
может написать или прочитать — поле `gameConfig`, имя сервиса в
`componentDependencies`, значение `control` формы, метод wasm-ABI, номер
порта, ключ блока снапшота — существует вечно. Вывод из эксплуатации = алиас
и адаптер, никогда не удаление. Нарушение И1 убило `v2 → v3`: набор
`control` **сократили** (`src/client/lib/formBuilder.js:6`).

**И2. Ничто новое не обязательно.** Каждое чтение движком данных плагина
идёт через аксессор со значением по умолчанию; каждый новый метод ядра
зовётся через feature-detect. Плагин любого возраста = все умолчания =
валиден. Нарушение И2 — растущий список обязательных путей в
`assertGameConfigShape` (`src/lib/gamePlugin.js:44-56`).

**И3. Форма данных неизменна — рядом добавляется новая.** Сигнатура
ABI-метода, раскладка байтов, форма объекта не меняются. Нужна другая форма
— это новое имя, старое продолжает работать.

**И4. Сам план ничего не ломает.** Ни один этап не бампает
`ENGINE_API_VERSION` и не отвергает плагин, который загружался раньше. Все
записи в `CHANGELOG.md` — `Added` / `Changed` / `Fixed`, ни одной
`⚠️ Breaking`. Если этап требует `⚠️ Breaking`, он спроектирован неверно.

**И5. Rust-трейты расширяются только методами с реализацией по умолчанию.**
Обязательный метод в `GameSim`/`GameClientDef` не даст скомпилироваться
крейту игры — это исходный слом, недопустимый без варианта «ничего не
делать».

**И6. Разделение бинарной и исходной совместимости.** Исходный API крейта
`vimp-engine-core` ломать по-прежнему можно: это затрагивает только игры,
которые сами решили пересобраться. Неприкосновенна **бинарная**
совместимость уже опубликованных `.wasm`. Это разделение — суть всего плана.

## Порядок и зависимости

Этапы 1–4 независимы друг от друга по коду, но **этап 1 идёт первым**: его
слепок и корпус — это сеть безопасности для всех последующих правок. Этап 5
идёт строго после 1–4: снимать гейт до того, как поверхность заморожена,
означает принимать старые плагины без гарантии, что они заработают. Этап 6
идёт последним и затрагивает чужие репозитории.

## Влияние на релиз

Затрагивается всё три публикуемых артефакта — при отчёте о работе это
обязано быть названо (правило «Release impact» в `CLAUDE.md`):

| Артефакт | Этапы | Уровень |
| --- | --- | --- |
| npm `vimp-engine` (0.22.1) | 1, 2, 3, 5 | minor (`Added`) |
| крейт `vimp-engine-core` (0.8.4) | 4 | minor (`Added`, макросы и трейт-методы с дефолтом) |
| npm `create-vimp-game` | 3, 5, 6 | patch/minor (шаблон и правила контракта) |

Бамп крейта означает, что репозитории игр должны последовать —
но **по своему желанию и в своём темпе**: старые сборки продолжают
работать, это и есть проверяемый результат плана. `ENGINE_API_VERSION`
остаётся равным **4** навсегда.

Версии не правятся руками и ничего не публикуется — этим занимается
разработчик через `npm run release` (`docs/en/publishing.md`).

## Итоговая проверка (по завершении всех этапов)

- `npx eslint .` и `npm test` — зелёные.
- `npm run core:test` — обязательно (этап 4 трогает крейт).
- Корпус совместимости из этапа 1 зелёный на всех поколениях фикстур.
- `npm run sim -- --game <dist vimp-tanks>` и то же для `vimp-snakes` —
  headless-матч проходит.
- Ручной браузерный smoke: `npm run dev`, обе игры видны в лобби, комната
  создаётся, матч идёт.
- Контрольный опыт, ради которого всё делалось: взять **опубликованную
  сборку игры под `engineApi: 3`** (до бампа v4), положить в `node_modules`
  и убедиться, что она появляется в лобби и играется.
