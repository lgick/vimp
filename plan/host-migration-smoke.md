# План: ручной smoke-прогон миграции хоста

Единственное, что осталось от направления «динамический хост»: живой
прогон в браузере. Сводит в один список все ручные проверки, которые
висели в закрытых планах:

- `plan/done/host-migration/stage_11.md` → п. 11.3 (18 сценариев, они же
  `docs/en/host.md` → «Manual run checklist» → «Rooms, links and
  migration»);
- ручные «Проверки» этапов 7, 8 (8e), 9, 10 того же плана;
- `plan/done/host-migration-review-2/stage_6.md` (сценарии A–L по находкам
  F2–F13, N1, N5, N6, N9 — контекст в `review.md` рядом и в
  `plan/done/host-migration-review/review.md`).

У каждого сценария в колонке «Источник» — откуда он пришёл
(`11.3#N` — п. 11.3, `R2-X` — ревью-2, `э.N` — проверка этапа N).
Дубликаты слиты в один сценарий.

> **Зачем.** `client/main.js` исполняется при импорте и в юнит-тесты не
> поднимается; модули `client/session/*` покрыты по отдельности, а их
> связи (поздние геттеры `getHandoff`/`getPromotion`/`getGuest`, общий
> `roomCtx`, порядок `bind()`), реальный WebRTC, `beforeunload`/`pagehide`,
> троттлинг CPU/сети и рестарт мастера проверит только живой прогон.

> **Как исполнять.** Выполняет разработчик (или агент через Claude in
> Chrome — тогда каждый сценарий записывается GIF'ом). Блоки независимы,
> порядок — рекомендуемый. Результат каждого сценария — в таблицу
> «Результаты»; блок помечается «✅ выполнен», когда все его сценарии ✅
> или осознанно отмечены «не проверялось» с причиной. Код этим планом не
> меняется; найденные баги — см. «После прогона».

## Подготовка

Dev-контур — `docs/en/getting-started.md`:

1. Плагины `@vimp-games/tanks` и `@vimp-games/snakes` слинкованы в обе
   стороны (`npm link`; dev-мастер отдаёт исходники плагина через
   `/@fs/`), ядра игр собраны (`npm run core:build` в репозитории игры).
   В обеих играх для блоков 3–4 включён `gameConfig.migration.midRound:
true` (если opt-in в репозитории игры ещё не сделан — включить
   локально, не коммитить).
2. `npm run dev:auth` (auth на Postgres, миграции — `npm run
auth:db:migrate`) и `npm run dev` (мастер, `https://localhost:3002`,
   mkcert-сертификаты).
3. Три профиля Chrome + Firefox, каждый залогинен **своим** аккаунтом
   (P1…P4) через закладку
   `http://localhost:3010/dev/login?nick=P<N>&returnUrl=https://localhost:3002/`
   — голоса и отчёты о недоступном хосте считаются по пользователям.
4. В каждой вкладке открыта консоль (фильтр `[worker]`, `[promotion]`,
   `[handoff]`, `[standby]`, `[session]`).
5. По умолчанию: P1 — создатель/хост, P2 — бета (в её консоли
   `standby received`), P3 — гость или лобби-наблюдатель.

## После прогона

1. Найденные баги — отдельным планом исправлений (`plan/<name>/` по
   образцу `plan/done/host-migration-review-2/`: тест первым, доки en/ru,
   правка записей `[Unreleased]` в `packages/engine/CHANGELOG.md`) или
   задачами — по решению разработчика.
2. Когда все блоки «✅ выполнен» — файл переносится в
   `plan/done/host-migration-smoke.md` (`git mv`, если под git, иначе
   `mv`), строка — в `plan/done/README.md`.

## Release impact

Кода нет — артефакты не трогаются. Релиз npm `vimp-engine` 0.36.0 (minor,
`### ⚠️ Breaking` в `[Unreleased]`) разумно делать после этого прогона.
