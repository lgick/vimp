## Часть 1. Значимые находки ✅ выполнены

### R4-1. Регрессия: новый разбор CSS теряет первое правило таблицы ✅ выполнен

**Факт.** `tests/client/gameShell.test.js:29` — снятие at-правил:

```js
.replace(/@[\w-]+[^{]*\{((?:[^{}]*\{[^{}]*\})*[^{}]*)\}/g, '$1')
```

Регулярка предполагает, что за именем at-правила всегда идёт блок. В
`packages/engine/src/client/style.css:1` стоит `@charset "UTF-8";` — at-правило
**без блока**. `[^{]*` проходит сквозь точку с запятой и весь текст до первой
`{` в файле, то есть до открывающей скобки **первого настоящего правила**, и
матч съедает `@charset "UTF-8"; … html, body {…}` целиком, оставляя вместо
него только тело первого правила.

Проверено прогоном самого парсера на настоящем `style.css`:

```
total rules: 113
[
 ["width: 100%;\n  height: 100%;\n  padding: 0;\n  margin: 0;\n\n\nbody",
  "background-color: #000; …"],
 [".vimp-shell > *", "display: none;"],
 …
]
```

Правило `html, body { … }` из разбора **исчезло**, а селектор следующего за
ним `body { … }` склеился с телом предыдущего в мусорную строку. С правильным
разбором правил 114, и первые две записи — `["html,\nbody", …]` и
`["body", …]`.

**Следствия.**

1. **Заявленная в R3-5 цель не достигнута полностью.** Слепой участок не
   исчез, а переехал: раньше не проверялось содержимое `@media`, теперь не
   проверяется первое правило файла. Если завтра `html, body` или соседнее с
   ним правило получит `display`, единственная страховка от повторения P1-1
   (чёрный экран в контейнере SDK) его не увидит.
2. **Новый тест это не ловит** (`gameShell.test.js:138-150`): фикстура
   `'#a { … } @media … { … } #c { … }'` не содержит ни одного statement
   at-правила, поэтому проверяет только ту половину разбора, которая работает.
3. Тесты зелёные и сегодня останутся зелёными — сломанной оказалась ровно та
   пара правил, на которую ни одна ассерция не смотрит. Это и делает находку
   значимой: тест-страховка тихо ослабла.

**Решение.** Statement at-правила (`@charset`, `@import`, `@namespace`,
`@layer a;`) снимаются отдельным проходом **до** разворачивания блочных.
Разделитель `[^;{]*` останавливается и на `;`, и на `{`, поэтому проход не
трогает `@media`/`@keyframes`/`@supports` (их заголовок упирается в `{`
раньше, чем в `;`):

```js
const cssRules = source =>
  source
    .replace(/\/\*[\s\S]*?\*\//g, '')
    // at-правила без блока (@charset/@import/@layer a;) снимаются первыми:
    // иначе `[^{]*` следующей регулярки пройдёт сквозь `;` до скобки
    // ПЕРВОГО настоящего правила и съест его вместе с селектором
    .replace(/@[\w-]+[^;{]*;/g, '')
    // тело блочного at-правила поднимается на верхний уровень вместе со
    // своими правилами, сам заголовок (@media …) выбрасывается
    .replace(/@[\w-]+[^{]*\{((?:[^{}]*\{[^{}]*\})*[^{}]*)\}/g, '$1')
    .split('}')
    .map(chunk => chunk.split('{'))
    .filter(parts => parts.length === 2)
    .map(([selector, body]) => [selector.trim(), body.trim()]);
```

Проверено на настоящем `style.css` (114 правил, `html, body` и `body`
разбираются корректно) и на обеих фикстурах.

**Тест.** В существующий кейс «разбор CSS видит правила внутри at-правил»
добавить statement at-правило в начало фикстуры — то есть воспроизвести
ровно форму настоящего файла:

```js
  it('разбор CSS видит правила внутри at-правил', () => {
    const rules = cssRules(
      '@charset "UTF-8"; #a { color: red; } @media (max-width: 1px) { #stat { display: block; } #b { color: blue; } } #c { color: green; }',
    );

    expect(rules).toContainEqual(['#stat', 'display: block;']);
    // @charset без блока не должен съедать первое настоящее правило
    expect(rules.map(([selector]) => selector)).toEqual([
      '#a',
      '#stat',
      '#b',
      '#c',
    ]);
  });
```

Без правки этот кейс красный (`#a` пропадает), с правкой — зелёный.

### R4-2. Петля перезагрузок закрыта на двух кодах из четырёх ✅ выполнен

**Факт.** `POLICY_CLOSE_INFORMS` (`client/main.js:1184-1187`) знает 4008 и
4009. Dedicated-контур закрывает сокет ещё двумя кодами:

- `dedicated/main.js:293` — `ws.close(4001, 'invalidOrigin')`;
- `host/PortMachine.js:70` — `close(socketId, 4006, 'roomFull', …)`.

Оба уезжают клиенту тем же путём и оба попадают в ветку «перезагрузиться
через 3 с» (`main.js:1249`).

**Следствия.**

1. **4001 — петля без выхода.** Origin страницы перезагрузка не меняет,
   поэтому цикл «reload → 4001 → reload» вечен, а игрок видит вводящее в
   заблуждение «The match is over — connection to the host is closed.»
   Косвенно цикл гасится только тем, что за ~30 перезагрузок вкладка сама
   упирается в лимит подключений и получает 4009 — то есть спасает случайность,
   и текст на выходе будет уже про «слишком много соединений», хотя причина
   была другая.
2. **4006 — петля, которая ест лимит.** Причину игрок видит верную (её
   доставляет `TECH_INFORM` до закрытия, `terminalInformShown` её сохраняет),
   но каждая перезагрузка — это новое соединение и новый `CONFIG_DATA`; через
   30 витков полная комната превращается в «Too many connections from your
   address», и человек, честно ждавший слот, получает сообщение про
   злоупотребление. Ровно тот сценарий усиления, ради которого R3-1 и делался.

**Решение.** Разделить два разных вопроса, которые сейчас отвечает один
объект: «какой текст показать» и «перезагружаться ли». Множество кодов, на
которых перезагрузка бессмысленна, шире карты сообщений:

```js
// отказы политики dedicated-сервера (src/dedicated/main.js, host/PortMachine.js):
// перезагрузка их не лечит — лимит частоты подключений съел бы ей же очередное
// соединение, таймаут хендшейка запустился бы заново, origin страницы не
// меняется вовсе, а слот в полной комнате перезагрузка не освобождает
const NO_RELOAD_CLOSE_CODES = new Set([4001, 4006, 4008, 4009]);

// текст — только там, где сервер его не прислал сам (4006 приносит причину
// TECH_INFORM'ом до закрытия). Текст здесь, а не в techInformList: список
// переопределяет игра, движковый индекс у неё дал бы «Unknown error»
const POLICY_CLOSE_INFORMS = {
  4001: 'This page is not allowed by the game server. Check the address you opened.',
  4008: 'Idle connection closed before the match started. Reload the page when you are ready to play.',
  4009: 'Too many connections from your address. Wait a minute and reload the page.',
};
```

и в `handleDisconnect`:

```js
  const policyInform = POLICY_CLOSE_INFORMS[closeCode];

  // терминальную причину закрытия (кик, полная комната) не затираем
  if (!terminalInformShown) {
    socketMethods[PS_TECH_INFORM_DATA](
      policyInform ??
        (isLobbyMode
          ? 'Host left — the room is closed. Returning to lobby…'
          : 'The match is over — connection to the host is closed.'),
    );
  }

  // в solo перезагружаться некуда: лобби нет, а матч поднимается с нуля.
  // В dedicated сервер жив — переподключение перезагрузкой уместно, но не
  // тогда, когда он сам нас и отбил по политике
  if (bootMode !== 'solo' && !NO_RELOAD_CLOSE_CODES.has(closeCode)) {
    setTimeout(() => location.reload(), 3000);
  }
```

Контуры P2P и solo не задеты: там `closeCode` — `undefined`, а
`Set.has(undefined)` — `false`.

**Тесты** (`tests/client/…`, там же, где уже проверяется доставка кода): кейс
на то, что 4006 не перезагружает страницу и **не** затирает пришедшую с
сервера причину, и кейс на 4001 с собственным текстом. Если прямого теста на
`handleDisconnect` в наборе нет, минимум — вынести `NO_RELOAD_CLOSE_CODES` и
`POLICY_CLOSE_INFORMS` в проверяемый модуль либо покрыть кейсом на уровне
`WebSocketTransport` + фейкового `location`.

**Документация.** `docs/en|ru/dedicated.md` — в абзаце «Оба отказа закрывают
сокет кодом, который клиент понимает» перечислить все четыре кода и сказать,
что у 4006 текст приходит от сервера, а не из `POLICY_CLOSE_INFORMS`.
`docs/en|ru/client.md` — тот же список в пункте «Разрыв P2P».

## Часть 2. Мелкие находки ✅ выполнены

### R4-3. В сигналинге `ws.on('error')` вешается позже двух `terminate()` ✅ выполнен

**Факт.** `SignalingServer.handleConnection` ставит слушатель ошибок сокета в
самом конце (`SignalingServer.js:130-132`), а обе ветки досрочного отказа —
`!requestOrigin` (`:72-75`) и новая `!ip` (`:79-82`) — зовут `ws.terminate()`
и делают `return` **до** этого. Соседний контур поступает наоборот и объясняет
почему: `dedicated/main.js:255-261` вешает `ws.on('error')` первой строкой
обработчика, с комментарием «Ставится до проверки origin: иначе ошибка на
отбитом соединении не перехвачена». Тот же класс P1-4 (`uncaughtException`),
который этот же коммит закрывает в CHANGELOG.

Отдельная ирония: новая ветка `!ip` срабатывает ровно тогда, когда
`remoteAddress` уже пуст, то есть **на уже разорванном сокете** — самом
вероятном источнике позднего `ECONNRESET`.

**Решение.** Поднять слушатель в начало метода (три строки):

```js
  handleConnection(ws, req) {
    // до любых ранних return'ов: ws эмитит 'error' на самом сокете, и без
    // слушателя один сорванный клиент — uncaughtException (тот же порядок,
    // что в src/dedicated/main.js)
    ws.on('error', error => {
      console.error('Signaling WebSocket error:', error);
    });

    const ip = clientIp(req, { trustProxy: this._trustProxy });
    …
```

и убрать прежний блок в конце.

**Тест** (`tests/master/SignalingServer.test.js`): в `FakeWs` добавить учёт
подписок и проверить, что после `handleConnection` с `socket: {}` слушатель
`error` уже стоит (`expect(ws.listeners('error')).toHaveLength(1)` или аналог
существующего в файле стиля).

### R4-4. Отсутствие `X-Real-IP` за прокси схлопывает мастер в одну комнату ✅ выполнен

**Факт.** `clientIp` при `trustProxy: true` и пустом `X-Real-IP` молча
откатывается на `req.socket.remoteAddress`
(`packages/engine/src/lib/clientIp.js:19-21`). За обратным прокси это адрес
самого прокси — `127.0.0.1` для **всех** клиентов сразу. Ключ используется в
двух местах: `RateLimiter` пингов и правило «одна комната на IP»
(`HostRegistry.add:38` → `getByIp:82-86`).

**Следствие.** Если перед мастером окажется прокси, не ставящий `X-Real-IP`
(старый `/etc/nginx/vimp.template` — `add-server.sh:493` прямо признаёт, что
на действующих серверах шаблон бывает старым; сторонний балансировщик; CDN),
то на всём мастере сможет существовать **ровно одна комната**, а лимит пингов
станет общим на всех. До правки такого режима не было: Nginx дописывал
`$remote_addr` в `X-Forwarded-For`, и у клиента без своего заголовка первый
хоп был настоящим адресом. То есть правка обменяла дыру в безопасности на
хрупкость развёртывания — обмен верный, но односторонний отказ стоит сделать
заметным.

**Решение.** Предупреждение один раз на процесс — дешевле и честнее, чем
молчаливая деградация:

```js
// src/lib/clientIp.js
let proxyHeaderWarned = false;

export function clientIp(req, { trustProxy = false } = {}) {
  const header = trustProxy ? req.headers['x-real-ip'] : undefined;

  // за прокси без X-Real-IP ключом станет адрес самого прокси, то есть один
  // общий бакет на всех клиентов: «одна комната на IP» пустит одну комнату
  // на весь мастер. Тихо это ронять нельзя — но и падать на первом запросе
  // тоже, поэтому предупреждаем один раз за процесс
  if (trustProxy && !header && !proxyHeaderWarned) {
    proxyHeaderWarned = true;
    console.warn(
      '[clientIp] trustProxy включён, но X-Real-IP не пришёл: ' +
        'ключ rate-limit\'ов стал адресом прокси, общим для всех клиентов. ' +
        'Проверьте proxy_set_header X-Real-IP $remote_addr.',
    );
  }

  return String(header || req.socket?.remoteAddress || '').trim();
}
```

Копию в `packages/auth/src/lib/clientIp.js` править так же.

**Тест** (`tests/lib/clientIp.test.js`): кейс на то, что при `trustProxy` без
заголовка `console.warn` зовётся, и **ровно один раз** на несколько вызовов
(модуль импортируется свежим через `vi.resetModules()`), — иначе предупреждение
превратится в лог-флуд на каждое соединение.

**Документация.** `docs/en|ru/deployment.md` (или врезка в `master.md`, где
уже описан ключ): `proxy_set_header X-Real-IP $remote_addr` — обязательная
строка для любого прокси перед мастером, dedicated или auth; без неё лимиты
схлопываются в один бакет.

### R4-5. В auth пустой ключ лимита не обрабатывается ✅ выполнен

**Факт.** `packages/auth/src/main.js:100-109` зовёт
`limiter.consume(clientIp(...))` без проверки на `''`. Мастер и dedicated в
этом же коммите такое соединение обрывают, auth — считает `''` полноценным
ключом.

**Следствие.** Мелкое, но асимметричное: запросы с уже разорванным сокетом
(клиент отвалился до обработки) делят один бакет `''`, и пять таких обрывов в
минуту начинают отдавать `429` друг другу. На поведение живых клиентов не
влияет, но это ровно та «дыра общего бакета», которую правка закрывала в двух
других местах.

**Решение.** Одна ветка в `rateLimit`, симметрично остальным:

```js
function rateLimit(limiter) {
  return (req, res, next) => {
    const ip = clientIp(req, { trustProxy: isProduction });

    // адреса нет только у уже разорванного сокета: общий бакет '' раздал бы
    // всем таким запросам один лимит (тот же приём, что в мастере и dedicated)
    if (!ip || !limiter.consume(ip)) {
      res.status(429).json({ error: 'rateLimited' });
      return;
    }

    next();
  };
}
```

**Тест** (`tests/auth/…`, там же, где проверяются лимиты): запрос с
`socket: {}` получает 429 и **не** попадает в общий бакет живых клиентов.
