## Часть 1. Значимые находки ✅ выполнены

### R5-1. Контракт кодов закрытия размножен по четырём файлам без единого источника ✅ выполнен

**Факт.** После правки набор «политических» кодов существует в пяти местах, и
ни одно из них не знает про остальные:

| Где | Что |
| --- | --- |
| `dedicated/main.js:283, 293, 305` | 4009, 4001, 4008 — литералами |
| `host/PortMachine.js:70` | 4006 — литералом |
| `host/HostGame.js:282, 293, 442` | 4003, 4004, 4005 — литералами |
| `master/SignalingServer.js:99, 152, 423` | 4001, 4000, 4002 — литералами |
| `client/network/policyClose.js:20, 22` | 4001/4006/4008/4009 — литералами |

Проверка «а не забыт ли код» — только глазами. Тест `policyClose.test.js`
проверяет ровно то, что в модуле уже написано: он не может знать, какие коды
шлёт сервер, поэтому новый код закрытия на серверной стороне пройдёт мимо
него молча — и петля перезагрузок, ради которой всё делалось, вернётся ровно
тем же способом, каким она возникла в первый раз (4001 и 4006 добавили
позже 4008/4009 и про клиент забыли).

У проекта есть **точный прецедент решения**:
`packages/engine/src/config/gameCodes.js` — «общий контракт хоста
(`SocketManager`) и клиента (`main.js`): значение не должно расходиться между
ними молча». Коды закрытия — тот же самый случай, только контракт шире.
Заодно видно, что 4007 не занят никем: номер пропущен, и по литералам это не
читается.

**Второе следствие — доки.** Канонический список кодов закрытия живёт в
`docs/en/network.md:171-173` и `docs/ru/network.md:102` («ports, frame format,
opcodes → `network.md`» по `CLAUDE.md`), и там до сих пор только
`4003`/`4004`/`4005`/`4006`. Коммит поменял реакцию клиента на 4006 —
страницу, которую правило доков прямо назначает для этого, он не тронул, а
про 4000/4001/4002/4008/4009 в `network.md` нет ни строки.

**Решение.**

1. Новый `packages/engine/src/config/closeCodes.js` — плоская карта, ровно по
   образцу `gameCodes.js`. Модуль изоморфный (объект без зависимостей),
   поэтому его одинаково видят Worker-safe `host/`, серверные контуры и
   клиент; `PortMachine.js:8` уже импортирует `../config/wsports.js`, путь
   тот же:

```js
// коды закрытия транспорта — общий контракт серверных контуров и клиента
// (тот же приём, что в gameCodes.js): значение не должно расходиться между
// ними молча. Отказы политики (клиент их не лечит перезагрузкой, см.
// client/network/policyClose.js) вынесены в POLICY отдельным списком
export default {
  staleHost: 4000, // master/SignalingServer.js — сигнальный WS хоста
  invalidOrigin: 4001, // master/SignalingServer.js, dedicated/main.js
  blocked: 4002, // master/SignalingServer.js — хостер заблокирован рейтингом
  kickForMaxLatency: 4003, // host/HostGame.js
  kickForMissedPings: 4004, // host/HostGame.js
  kickIdle: 4005, // host/HostGame.js
  roomFull: 4006, // host/PortMachine.js
  // 4007 свободен
  handshakeTimeout: 4008, // dedicated/main.js
  tooManyConnections: 4009, // dedicated/main.js
};
```

2. Все пять файлов из таблицы переводятся на именованные константы
   (`closeCodes.roomFull` вместо `4006` и т.д.) — правка механическая, тесты
   на кодах не меняются, потому что значения те же.

3. `policyClose.js` собирает множество из карты, а не из литералов:

```js
import closeCodes from '../../config/closeCodes.js';

const { invalidOrigin, roomFull, handshakeTimeout, tooManyConnections } =
  closeCodes;

const NO_RELOAD_CLOSE_CODES = new Set([
  invalidOrigin,
  roomFull,
  handshakeTimeout,
  tooManyConnections,
]);
```

4. Тест-страховка, которой сейчас нет (`tests/client/network/policyClose.test.js`):
   пройтись по всем кодам из `closeCodes` и потребовать явного решения по
   каждому — чтобы новый код нельзя было добавить, не заглянув в клиент:

```js
  // новый код закрытия обязан быть осознанно отнесён к одной из двух групп:
  // иначе он молча попадёт в «перезагружаемся», как когда-то 4001 и 4006
  it('каждый код из config/closeCodes.js классифицирован', () => {
    const decided = new Set([
      // перезагрузка уместна: обрыв, кик, протухший хост
      closeCodes.staleHost,
      closeCodes.kickForMaxLatency,
      closeCodes.kickForMissedPings,
      closeCodes.kickIdle,
      // перезагрузка бессмысленна
      closeCodes.invalidOrigin,
      closeCodes.blocked,
      closeCodes.roomFull,
      closeCodes.handshakeTimeout,
      closeCodes.tooManyConnections,
    ]);

    expect(new Set(Object.values(closeCodes))).toEqual(decided);
  });
```

5. Доки: `docs/en|ru/network.md` — полный список кодов таблицей (код, кто
   шлёт, что делает клиент) со ссылкой на `client/network/policyClose.js`;
   в `dedicated.md`/`client.md` длинные перечисления кодов заменяются
   ссылкой на неё, чтобы список жил в одном месте и в доках тоже.

**Цена.** Одна новая карта на 9 строк плюс механическая замена литералов;
поведение не меняется ни в одном контуре, все существующие тесты остаются
валидными.

### R5-2. Обоснование «у 4006 текста нет» не соответствует механизму, и из-за этого потерян запасной текст ✅ выполнен

**Факт.** И комментарий в `policyClose.js:14-17`, и обе локали
`dedicated.md`/`client.md` объясняют отсутствие 4006 в `POLICY_CLOSE_INFORMS`
так: движковый текст «затёр бы» пришедшую с сервера причину. Код так не
работает:

```js
  const policyInform = POLICY_CLOSE_INFORMS[closeCode];

  // терминальную причину закрытия (кик, полная комната) не затираем
  if (!terminalInformShown) {
    socketMethods[PS_TECH_INFORM_DATA](policyInform ?? (…));
  }
```

Затирание уже исключено внешним `if`: как только сервер прислал терминальный
`TECH_INFORM` (`main.js:671` ставит `terminalInformShown = true` на любом
ключе, кроме `loading`), `handleDisconnect` не пишет **ничего** — независимо
от того, есть запись в карте или нет. То есть `POLICY_CLOSE_INFORMS` по
факту не «карта текстов вместо серверных», а **карта запасных текстов на
случай, когда сервер причину не прислал**.

**Следствие.** Ровно в том случае, ради которого запасной текст и нужен —
`TECH_INFORM` не доехал (кадр потерян на закрывающемся сокете, транспорт без
`TECH_INFORM` перед `close`, чужая реализация серверной стороны) — игрок при
4006 видит `The match is over — connection to the host is closed.` вместо
«комната полна» и при этом никуда не перезагружается. Сообщение
дезинформирует именно в той ветке, которую правка R4-2 обслуживает.

Практическая вероятность низкая (в сегодняшнем dedicated кадр уходит первым
и TCP гарантирует порядок), но цена исправления — одна строка, а цена
неверного комментария выше: следующий, кто будет добавлять код закрытия,
воспроизведёт «раз текст приходит с сервера — в карту не кладём» уже там,
где никакого `terminalInformShown` не будет.

**Решение.** Вернуть 4006 в карту как запасной текст и исправить объяснение —
в модуле и в обеих локалях обеих страниц:

```js
// Тексты — запасные: `handleDisconnect` пишет их только тогда, когда сервер
// причину не прислал сам (`terminalInformShown`). Полная комната приезжает с
// причиной от порт-машины (`TECH_INFORM` перед `close`), и она всегда
// побеждает — запись ниже отработает, только если тот кадр не доехал
export const POLICY_CLOSE_INFORMS = {
  4001: 'This page is not allowed by the game server. Check the address you opened.',
  4006: 'The room is full. Try again later.',
  4008: 'Idle connection closed before the match started. Reload the page when you are ready to play.',
  4009: 'Too many connections from your address. Wait a minute and reload the page.',
};
```

**Тест.** Кейс `'у 4006 текста нет: причину приносит TECH_INFORM перед
закрытием'` заменяется на обратный по смыслу — текст есть у **всех** кодов
запрета перезагрузки:

```js
  it('запасной текст есть у каждого кода запрета перезагрузки', () => {
    for (const code of [4001, 4006, 4008, 4009]) {
      expect(POLICY_CLOSE_INFORMS[code], String(code)).toBeTruthy();
    }
  });
```

Кейс «каждому тексту соответствует запрет перезагрузки» остаётся как есть и
становится точной обратной проверкой (карта и множество совпадают).

**Альтернатива (минимальная).** Если запасной текст решено не добавлять,
исправить придётся всё равно — комментарий в `policyClose.js` и абзацы в
`docs/en|ru/dedicated.md`, `docs/en|ru/client.md`: причина исключения 4006 не
«затёрло бы», а «серверный текст конкретнее и приходит всегда». Рекомендуется
первый вариант: он делает утверждение доков верным без оговорок.

### R5-4. Регулярка statement at-правил шире, чем задача ✅ выполнен

**Факт.** `tests/client/gameShell.test.js:31` — `/@[\w-]+[^;{]*;/g` снимает
**любую** последовательность «`@слово` … `;`», а не только statement
at-правила. Внутри объявления это тоже срабатывает: `background:
url(https://user@host/pic.png);` потеряет хвост `@host/pic.png);`, а
`content: "@media";` — часть строки. Скобки при этом не трогаются, поэтому
разбор не развалится — он молча потеряет объявление, а страховка от P1-1
проверяет именно объявления (`display`, `position` и т.п.).

Сегодня в `style.css` таких значений нет — находка предупредительная, ровно
как R4-1 была предупредительной до `@charset`.

**Решение.** Ограничить проход известным списком statement at-правил (все
остальные at-правила блочные и до `;` не доходят):

```js
    // at-правила без блока (@charset/@import/@namespace/@layer a;) снимаются
    // первыми: иначе `[^{]*` следующей регулярки прошла бы сквозь `;` до
    // скобки ПЕРВОГО настоящего правила и съела бы его вместе с селектором
    // (review-4.md, R4-1). Список закрытый, чтобы `@` внутри url()/строки
    // не выглядел для регулярки началом at-правила (review-5.md, R5-4)
    .replace(/@(charset|import|namespace|layer)\b[^;{]*;/g, '')
```

Фикстура кейса не меняется и остаётся зелёной.

**Факт.** Флаг `proxyHeaderWarned` живёт в модуле, а оба файла
(`tests/lib/clientIp.test.js`, `tests/auth/clientIp.test.js`) держат
статический импорт `clientIp` наверху и пользуются им в первом `describe`.
Кейс «пустой `X-Real-IP` за прокси не отменяет адрес сокета» уже ходит по
ветке предупреждения и **сжигает** флаг статически импортированной копии;
второй `describe` спасается только тем, что берёт модуль заново через
`vi.resetModules()`.

Пока ассерций на `console.warn` в первом `describe` нет, всё зелено. Любая
добавленная туда проверка предупреждения окажется зависящей от порядка
кейсов в файле — то есть тест будет красным или зелёным в зависимости от
того, куда его вставили. Для файла, который сам проверяет «ровно один раз на
процесс», это неприятная ловушка.

**Решение.** Свежий модуль для **каждого** кейса, статический импорт убрать
(оба файла, пути отличаются):

```js
import { describe, it, expect, beforeEach, afterEach, vi } from 'vitest';

const MODULE = '../../packages/engine/src/lib/clientIp.js';

// флаг «уже предупредили» живёт в модуле: без свежего импорта на каждый кейс
// результат зависел бы от порядка кейсов в файле (review-5.md, R5-5)
let clientIp;

beforeEach(async () => {
  vi.resetModules();
  vi.spyOn(console, 'warn').mockImplementation(() => {});
  ({ clientIp } = await import(MODULE));
});

afterEach(() => {
  vi.restoreAllMocks();
});
```

Локальный хелпер `freshClientIp` во втором `describe` после этого не нужен.
