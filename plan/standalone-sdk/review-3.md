## Часть 1. Значимая находка

### R3-1. Лимит подключений dedicated ключуется по заголовку, который задаёт клиент ✅ выполнен

**Факт.** `src/dedicated/main.js:271-272`:

```js
const ipHeader = req.headers['x-forwarded-for'] || req.socket.remoteAddress;
const ip = String(ipHeader ?? '').split(',')[0].trim();
```

Nginx деплоя ставит заголовок так
(`.github/deployment/install-system.sh:439`):

```nginx
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
```

`$proxy_add_x_forwarded_for` — это **заголовок клиента плюс дописанный через
запятую `$remote_addr`**. Значит за Nginx первый элемент списка — ровно то,
что прислал клиент, а реальный адрес идёт последним. Разбор «первый хоп»
корректен только при `proxy_set_header X-Forwarded-For $remote_addr` (замена),
чего в деплое нет.

**Следствия.**

1. **Обход тривиален и безусловен.** Достаточно слать на каждое соединение
   свой `X-Forwarded-For: 10.0.0.<n>` — каждое получает свежий бакет, лимит
   30/мин не срабатывает никогда. То самое усиление, ради которого лимит и
   вводился (каждое соединение стоит серверу `CONFIG_DATA` до всякой
   аутентификации), остаётся открытым.
2. **Появился новый вектор, которого до коммита не было: точечная блокировка
   игрока.** 30 соединений с `X-Forwarded-For: <адрес жертвы>` за минуту
   выбирают её бакет; настоящий запрос жертвы (у неё своего заголовка нет,
   Nginx подставит её адрес первым и единственным) закрывается кодом 4009. В
   `dedicated` клиент на закрытие показывает общее «The match is over…» и
   через 3 с делает `location.reload()` (`main.js:1229-1234`) — то есть жертва
   попадает в петлю перезагрузок ровно до конца окна, а атака повторяется
   каждую минуту. Знать адрес цели нужно, но это единственное условие: ни
   участия в матче, ни аутентификации не требуется.
3. **Доки утверждают обратное.** `docs/en/dedicated.md:134-137` и
   `docs/ru/dedicated.md:132-135`: «первый адрес `X-Forwarded-For` за Nginx
   (деплой его ставит)… При прямом соединении заголовок задаёт клиент». За
   Nginx он задаётся клиентом ровно так же — фраза даёт ложную гарантию
   владельцу сервера.

**Почему не поймал тест.** Кейс «частота подключений с адреса ограничена»
открывает 30 соединений **без** заголовка, поэтому меряет ветку
`req.socket.remoteAddress` — единственную, которая работает как задумано.

**Решение.** Заголовок, который Nginx этого деплоя **перезаписывает**, —
`X-Real-IP` (`proxy_set_header X-Real-IP $remote_addr` там же, строкой выше).
Ему за прокси можно верить, а без прокси нельзя вообще ничему, кроме адреса
сокета. Разбор один на три места, поэтому его стоит вынести:

```js
// src/lib/clientIp.js
// Адрес клиента для rate-limit'ов. X-Forwarded-For для этого не годится:
// Nginx деплоя ставит его через $proxy_add_x_forwarded_for, то есть
// ДОПИСЫВАЕТ реальный адрес к присланному клиентом — первый элемент списка
// задаёт сам клиент (обход лимита и блокировка чужого адреса). X-Real-IP тот
// же Nginx перезаписывает ($remote_addr), поэтому за прокси доверяем только
// ему, а вне прода — адресу сокета.
export function clientIp(req, { trustProxy = false } = {}) {
  const header = trustProxy ? req.headers['x-real-ip'] : undefined;

  return String(header || req.socket.remoteAddress || '');
}
```

в `src/dedicated/main.js`:

```js
    const ip = clientIp(req, { trustProxy: isProduction });

    // адреса нет только у уже разорванного сокета: общий бакет '' для таких
    // соединений был бы дырой в лимите
    if (!ip) {
      ws.terminate();
      return;
    }

    if (!connectionLimiter.consume(ip)) {
```

**Тесты** (`tests/dedicated/dedicatedServer.test.js`): те же 30 соединений, но
каждое со своим `headers: { 'x-forwarded-for': '10.0.0.' + i }` (опция `ws`) —
31-е всё равно закрывается кодом 4009; отдельным кейсом — `x-real-ip` вне
прода игнорируется.

**Документация:** в `docs/en|ru/dedicated.md` заменить абзац про ключ лимита:
ключ — адрес сокета, за Nginx — `X-Real-IP`, который прокси перезаписывает;
`X-Forwarded-For` не используется намеренно.

**Паритет (отдельным решением владельца).** Тот же разбор «первый хоп» стоит
в `src/master/SignalingServer.js:62-63` и `packages/auth/src/main.js:97-100` —
там он тоже обходится и тоже позволяет выбрать чужой бакет (у auth это лимиты
на перебор ников и старт OAuth). Правка обоих — три строки после появления
`clientIp`. Заодно закрывается пре-существующий бросок в сигналинге:
`ipHeader.split(...)` при отсутствующих заголовке и `remoteAddress` — это
`TypeError` внутри `handleConnection`, то есть `uncaughtException` (класс
P1-4). В dedicated этой ямы нет — там `String(x ?? '')`.

> **Решение владельца: правим везде** — dedicated, мастер и auth. Сделано:
> `src/lib/clientIp.js` (движок) и его копия `packages/auth/src/lib/clientIp.js`
> (auth не тянет рантайм-зависимость на движок — тот же приём, что у
> `rateLimiter.js`); `SignalingServer` получил опцию `trustProxy`, которую
> `lobby.js` передаёт как `isProduction`, и обрывает соединение без адреса;
> auth зовёт `clientIp(req, { trustProxy: isProduction })`. `X-Forwarded-For`
> в кодовой базе ключом больше нигде не является.
